Starship Processing

Important limitations before using these controls

  1. Only one tab can hold unsynced Raw JSON at a time: leaving a tab whose sync light is red (by mouse or keyboard) opens Unsynced Raw JSON with Sync, Abandon and Cancel. Sync applies the text and switches only if it succeeds; Abandon reloads that tab’s Raw JSON from the app data; Cancel stays on the tab. Structured operations still refuse while any tab is unsynced. Inventory Raw JSON can be synchronized and Pretty Printed like the other tabs, provided it keeps exactly the same inventories in the same order.
  2. If the Raw JSON is not valid JSON, Sync to Node View and Pretty Print show the error and stop: your text stays in the editor, the sync light stays red and Node View keeps showing the app data. Valid JSON that is not an array is refused with Raw JSON Not Applied. Valid JSON is also refused, with the reason and the entry number, when this app could not process it: every entry must be a JSON object with the fields the app reads (Name on every tab; GalacticAddress on Bases; UniverseAddress with RealityIndex and GalacticAddress numbers on Teleport Endpoints), Starships may hold at most 12 entries, and Inventory must keep its count and order. An empty array ([]) is applied like any other array on Bases, Starships and Teleport Endpoints; on Inventory it is refused by the count rule. Correct the text and retry, or leave the tab and choose Abandon to reload the app data.

Starship Processing → Node View → Upgrade Starships → Upgrade behavior notice

Upgrade behavior notice

Selected ships receive reference statistics and S-class settings. Non-Corvette technology items are replaced entirely with reference equipment; existing extras, trails, figurines and module seeds can be lost. Corvettes preserve equipment/build parts and add missing technology. Capacity targets 60 technology slots; equipment/capacity failure can skip that portion while statistics/class still apply. Unsupported models or invalid statistics/class references are rejected.

Starship Processing → Node View → Upgrade Starships → Starship checkboxes

Starship checkboxes

All checkboxes start unchecked; tree selection is not upgrade selection. Named occupied ships display only their saved Name: duplicate names can look identical, and the ownership index is stored invisibly rather than shown beside the name. Unoccupied slots display Slot N - (unoccupied); unnamed occupied slots use Starship N (unnamed).

Rows remain in ownership-list order, including empty slots. Identify the intended zero-based tree index before opening the picker; its row is that index plus one when counting every checkbox from the top, including unoccupied rows. Select only the confidently identified row; Cancel if uncertain. Empty selection and Cancel perform no upgrade.

OK

Before using OK, read the shared safety limitations for this page.

Starship Processing → Node View → Upgrade Starships → OK → Upgrading starships, please wait…

Upgrading starships, please wait…

The text-only notice reads exactly: Upgrading starships, please wait…

The upgrade controller owns this non-cancellable modal while reading references, planning, publishing changes and preparing results. It dismisses progress in cleanup before the result dialog or failure warning and restores interaction. The notice is not a live-save confirmation.

There are no Cancel or Close buttons in this notice. Wait for the owning operation to finish; no separate user-dismissal or cancellation control is provided here.

Lists owned-ship slots and nested ship data.

Starship Processing → Node View → Starship tree → Unoccupied slots

Unoccupied slots

The ordinary tree uses Starship N captions with the stored Name or No name provided; it does not display the Upgrade Starships picker’s occupancy-aware Slot X - (unoccupied) caption. Do not decide occupancy from the tree name alone.

Check Resource.Filename in the actual record: a named position can still be empty, while an unnamed ship can be occupied. In the Upgrade Starships picker/results, Slot X - (unoccupied) identifies an unoccupied position; this is not the ordinary tree label. Use the picker’s ownership order carefully and do not treat every unnamed record as empty.

Starship Processing → Node View → Starship tree → Left-button drag and drop

Left-button drag and drop

The shared tree supports structural drag and drop with parent-type and last-child guards. These generic checks are not proof that an arbitrary ship move preserves every game-side association. Use a backup and inspect results; the broader ship move/swap/sort design is separate from the deletion safeguards.

Delete Nodes — confirmation

Review Delete (N) nodes from the Tree? before acting. For a base or generic tree deletion the selected visible-node count can include expanded child fields. The starship-specific controller instead deduplicates complete occupied ship slots and validates the complete request.

Starship Processing → Node View → Right-click menu → Delete Node → Delete Nodes — confirmation → OK; also Starship Processing → Node View → Right-button drag selection → Delete N Nodes → Delete Nodes — confirmation → OK

OK

Confirms this deletion request. Generic deletion removes the chosen tree nodes in app memory unless the result would leave records the app cannot process, in which case it is refused with Node View Change Not Applied and Node View is restored; the top list row cannot be deleted. Starship deletion uses its guarded fixed-slot transaction instead. There is no automatic live save.

Copy This Node's Text

Copies the selected node’s displayed label to the clipboard. It does not serialize that node’s full JSON or export the complete record.

This command copies the visible label of the clicked node, not the node’s complete JSON subtree. To copy JSON, select the desired text in Raw JSON and use Copy; use the whole-context clipboard export only when that larger scope is intended.

Starship Processing → Node View → Starship tree → Right-click menu → Delete Node

Delete Node

Routes single Delete Node and right-drag requests through the same guarded fixed-slot starship-deletion controller and shared Delete Nodes confirmation. It accepts complete ownership-slot nodes, not isolated child fields or the ownership-list root; empty slots are no-ops. It preserves ownership-slot positions with empty templates and applies associated appearance/build cleanup. This changes app memory only.

The app refuses a request that would remove every occupied ship as a whole, with no partial deletion or override. The exact app-policy notice is “NMS does not allow that last ship to be deleted from inventory; aborting”. This describes the implemented policy, not independently verified game behavior.

Before using Delete Node, read the shared safety limitations for this page.

The guarded action checks all tabs’ synchronization flags and rejects unsynchronized work or a stale/changed request. Verify actual model values before any deletion.

Starship Processing → Raw JSON → Pretty Print

Pretty Print

Pretty Print is not display-only: it attempts a model update from the editor, reloads indented text from the model and rebuilds Node View.

Before using Pretty Print, read the shared safety limitations for this page.

If the text is invalid or refused (for example a changed Inventory count or a missing required field), Pretty Print shows the reason and stops without changing your text; the sync light stays red. Formatting does not write a game file; compare actual values before saving.

↑ This page’s hierarchy

Starship Processing → Raw JSON → JSON text editor

JSON text editor

Displays the loaded context’s ShipOwnership array. You can edit the JSON directly. Line numbers identify text lines; the current line is highlighted. Text is not line-wrapped, so long lines scroll horizontally.

Text editing is not an automatic model update or disk write. Pending text stays on its tab: you cannot switch tabs without choosing Sync, Abandon or Cancel, so a sync on another tab cannot overwrite it.

The editor displays line numbers and does not wrap long JSON lines. Use the editor’s own horizontal scrollbar to inspect a long value. Selecting or copying text does not edit the save; typing, cutting, deleting or pasting does. A text edit is not automatically a successful synchronization or a disk save.

Standard editing commands

Undo, Redo, Cut, Copy, Paste, Delete and Select All operate on the text editor, subject to its current selection and available edit history. These are text operations, not a general undo facility for tree operations.

Starship Processing → Raw JSON → Right-click menu → Standard editing commands → Undo

Undo

Reverses the most recent text-editor edit when an undo step is available. It is not an application-wide undo for sorting, upgrades, node deletion or inventory organization.
