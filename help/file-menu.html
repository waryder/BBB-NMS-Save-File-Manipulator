Main Window → Menu Bar → File → Open NMS Save File

Open NMS Save File

Opens the slot picker. It does not change the loaded app data until a load is confirmed.

Open Open NMS Save File help →

Main Window → Menu Bar → File → Open NMS Save File → Storage:

Storage:

Read-only platform label derived from the selected folder name: Steam for st_* accounts, GOG for DefaultUser, and Steam/GOG for another manually selected folder. It is blank without a folder. This is not a platform selector or proof that copied files belong to a particular account.

Main Window → Menu Bar → File → Open NMS Save File → Save Path:

Save Path:

Shows an existing remembered save-folder path. On first use, or when the remembered directory no longer exists, Save Path starts blank; the app does not silently select, load or remember another account. Use Pick Folder... to choose the intended folder.

Inside Pick Folder..., an existing accepted path remains the starting location. Otherwise the app suggests the conventional Steam st_* or GOG DefaultUser account with the newest readable positive embedded save-metadata timestamp under the normal Windows HelloGames/NMS location. Equal timestamps keep the first encountered account; filesystem Date modified is not the ranking criterion. If no candidate is usable, browse manually.

Main Window → Menu Bar → File → Open NMS Save File → Save Path: → Pick Folder...

Pick Folder...

Opens the native Pick NMS Save Folder directory chooser. The current existing selected folder wins as its starting location; otherwise discovery suggests the newest readable Steam/GOG account by embedded save timestamp. Suggestions are limited to ordinary st_* and DefaultUser account directories under the normal NMS root, not a recursive backup or all-platform search. You may browse elsewhere.

Folder discovery itself does not load data, remember a preference or replace app work. Cancel leaves the current path, dropdowns and preferences unchanged. Accepting a valid directory opens Confirm Preference Disk Write; only OK and a successful preference write update Save Path and rescan slots. Cancel defaults to no change. This does not retarget data already loaded for later saving.

Main Window → Menu Bar → File → Open NMS Save File → Save Path: → Pick Folder... → Pick NMS Save Folder — native folder chooser

Pick NMS Save Folder — native folder chooser

Select an existing directory. This is the operating system’s native directory chooser; layout, localization and acceptance/cancellation button labels can vary. The app supplies the title Pick NMS Save Folder, not fixed native button captions. Acceptance is not consent to write preferences or load game data.

An existing selected folder remains the starting location. Otherwise the suggestion follows the newest usable embedded save timestamp among conventional Steam and GOG accounts; no folder is loaded or remembered merely by opening this chooser. The first-use or missing remembered Save Path can be blank until you explicitly choose and confirm a folder.

Confirm Preference Disk Write

After native selection and directory validation, the app asks: About to write the remembered NMS save-folder preference: {folder} Continue? Here {folder} is the selected directory. Cancel is the default; choosing a folder alone is not persistence consent.

Main Window → Menu Bar → File → Open NMS Save File → Load Slot

Load Slot

Warns before replacing all currently loaded app data, including unsaved edits. Requires the slot’s Auto/Manual data files and both mf_ companions with valid positive timestamps. Selects the newer embedded timestamp. Successful confirmations close the picker before decoding and refreshing all four tabs.

Main Window → Menu Bar → File → Open NMS Save File → Load Slot → Equal save timestamps

Equal save timestamps

The Equal save timestamps warning reads exactly: the auto and manual save files appear to have the same timestamp; Hit Ok to load the manual save or Cancel to abandon this load

OK selects Manual for the load; Cancel is the default and abandons loading without an Auto fallback. These are embedded metadata timestamps, not filesystem modification times.

Main Window → Menu Bar → File → Open NMS Save File → Load Slot → Equal save timestamps → OK

OK

Selects the Manual file on an embedded-timestamp tie; it does not choose Auto or use filesystem times. After all load checks succeed, the Manual file’s active editable context replaces current app data. It does not write a live save.

Main Window → Menu Bar → File → Save NMS Save File

Save NMS Save File

For a loaded NMS source, writes the retained data file and its metadata companion, using the context selected at load. Browsing another folder afterward does not retarget this save. The inactive context and unrelated root data are preserved.

Main Window → Menu Bar → File → Save NMS Save File → Unsynchronized text check

Unsynchronized text check

Save checks all four tabs’ synchronization flags and refuses when any flag is false. A failed or refused sync keeps its flag red, so unapplied text blocks Save. Passing this check does not validate game-schema correctness; compare intended values before saving.

Only one tab can hold unsynced Raw JSON at a time: leaving a tab whose sync light is red (by mouse or keyboard) opens Unsynced Raw JSON with Sync, Abandon and Cancel. Sync applies the text and switches only if it succeeds; Abandon reloads that tab’s Raw JSON from the app data; Cancel stays on the tab. Structured operations still refuse while any tab is unsynced. Inventory Raw JSON can be synchronized and Pretty Printed like the other tabs, provided it keeps exactly the same inventories in the same order.

If the Raw JSON is not valid JSON, Sync to Node View and Pretty Print show the error and stop: your text stays in the editor, the sync light stays red and Node View keeps showing the app data. Valid JSON that is not an array is refused with Raw JSON Not Applied. Valid JSON is also refused, with the reason and the entry number, when this app could not process it: every entry must be a JSON object with the fields the app reads (Name on every tab; GalacticAddress on Bases; UniverseAddress with RealityIndex and GalacticAddress numbers on Teleport Endpoints), Starships may hold at most 12 entries, and Inventory must keep its count and order. An empty array ([]) is applied like any other array on Bases, Starships and Teleport Endpoints; on Inventory it is refused by the count rule. Correct the text and retry, or leave the tab and choose Abandon to reload the app data.

Worked use cases

  1. Save my changes back to the correct game file.
  2. Saving or another operation is blocked by unsynchronized text.

Main Window → Menu Bar → File → Save NMS Save File → Confirm Live Save Write

Confirm Live Save Write

The Confirm Live Save Write warning reads: This Save action will overwrite your live game save file data for slot {slot} ({context}). Be sure No Man's Sky is closed. Continue with the Save? The runtime {slot} is the retained loaded slot; {context} is Main or Expedition.

Cancel is the default. OK authorizes writing the retained source data/metadata pair after preflight checks; it is not consent to save to a newly browsed folder. Cancel declines before staging/writing, leaving current app data and retained source unchanged. Verify actual intended model values before consenting; green synchronization flags are not a validation guarantee.

Main Window → Menu Bar → File → Save NMS Save File → Confirm Live Save Write → OK

OK

Authorizes the live write to the retained loaded slot and its Main/Expedition context after synchronization-flag and unchanged-app-data checks. Keep No Man’s Sky closed. The confirmed data file and mf_ companion are staged/written and read back before success is reported. It is not a backup, not an atomic two-file replacement and not protection against external disk changes. Verify intended model values first; green flags alone do not prove a successful Raw JSON edit.

Cancel

Default action: declines the live write before staging or writing. Current app data, retained loaded source and indicators remain unchanged. This is not an undo for earlier operations or writes.

Main Window → Menu Bar → File → Full Live Save Backup

Full Live Save Backup

Creates a standard full live-save-folder backup after explicit confirmation. This is separate from exporting one base or inventory.

Main Window → Menu Bar → File → Full Live Save Backup → Source and destination proposal

Source and destination proposal

Shows the resolved full live NMS source tree, proposed timestamped backup destination and planning information before output creation. It uses an existing remembered folder, not just the loaded slot and not an unconfirmed discovery suggestion. If none is available, select and confirm a folder through File → Open NMS Save File first.

Selecting a conventional Steam st_* or GOG DefaultUser account inside NMS expands the backup source to the containing NMS directory, including its other accounts and root files. Read the actual proposed path; do not assume only one selected account or slot will be copied.

Worked use cases

  1. Find a save stored in a different folder or account.
  2. Make a full backup before trying an edit.
↑ This page’s hierarchy

Main Window → Menu Bar → File → Full Live Save Backup → Save

Save

Authorizes copying the proposed live disk tree into Backups\Full NMS Save Backups inside the app’s BBB NMS SFM Data storage folder. A progress notice covers copy and verification; completion reports the resulting directory. Unsaved editor data is not first written to disk and is not included as if it were saved.

Main Window → Menu Bar → File → Full Live Save Backup → Save → Backing up live save files, please wait…

Backing up live save files, please wait…

The text-only notice reads exactly: Backing up live save files, please wait…

The full-backup controller owns the modal copy/verification notice and dismisses it in cleanup before the completion or error notification. This copies the confirmed live disk tree, not pending editor text; progress alone is not a verified-success report.

There are no Cancel or Close buttons in this notice. Wait for the owning operation to finish; no separate user-dismissal or cancellation control is provided here.

Full Live Save Restore

Opens Full Live Save Restore — Manual Instructions. It is instructions-only, not an automated restore feature.

Main Window → Menu Bar → File → Full Live Save Restore → Manual instructions

Manual instructions

Read-only selectable text identifies the runtime backup root and live NMS directory, warns that the example deletes all live NMS directory contents, and describes copying a selected backup back into that directory. The app does not execute these commands. Do not run restoration commands with the game open.

Worked use cases

  1. Restore a full backup manually after an unsuccessful edit.
  2. Recover safely after an error without overwriting the backup or save I need.
