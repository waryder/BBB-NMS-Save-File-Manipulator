Saving or another operation is blocked by unsynchronized text.

Use case 56 · When something does not behave as expected

Help Index → When something does not behave as expected → Use case 56

A synchronization gate blocks an operation while a tab has unsynced Raw JSON. Only one tab can be unsynced at a time, because leaving it asks Sync, Abandon or Cancel.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Read the warning. Cancel unready write confirmations and keep NMS closed.
  2. Resolve any unsynced Raw JSON first: leaving a tab with a red sync light asks Sync, Abandon or Cancel. Decide which edits are wanted before any sync or reload.
  3. A parse error or refused text stops with a message, keeps your text and keeps the light red; [] is applied on Bases, Starships and Teleport Endpoints and refused on Inventory by the count rule. Verify actual values.
  4. Inventory Raw JSON can be synced if it keeps the same inventories in the same order. Organizer and Replace Items from Backup remain the simpler tools for moves and replacement.

Steps

  1. Inspect the Raw JSON synchronization status in all four processing tabs: bases, starships, inventories and teleport endpoints. A loaded-live indicator does not tell you that every editor matches the shared model. (control reference)
  2. Go to the tab with the red sync light. Sync it and verify the values, or leave it and choose Abandon to reload the app data. Inventory Raw JSON must keep the same inventories in the same order. (control reference)
  3. Wait for Processing to dismiss after each sync, then compare the exact edited value in tree and text against its preserved copy. After a parse error or refusal, the light stays red and your text is kept. [] is applied on Bases, Starships and Teleport Endpoints and refused on Inventory by the count rule. Correct and retry only understood edits, or preserve useful work and deliberately reload if abandoning them. (control reference)
  4. Retry the intended operation after resolving every pending tab. For File → Save, recheck the loaded slot and Main or Expedition context in the separate confirmation and accept only if all reviewed changes should be written. (control reference)

Expected result

  1. File → Save refuses unsynchronized text before requesting a live write. Organizer and guarded starship operations also require a synchronized source context.
  2. A cleared gate means the status checks passed, not that every intended edit survived. Verify the intended values before retrying the operation.

What changes, and when to save

Synchronization changes app memory only. Clearing this blocker is not a live-save completion; a separately confirmed File → Save and its verified result are still required. Verify intended values before saving.

Check the result

  1. Confirm every tab’s intended edits survived and the retried action produced its expected result. A green synchronization light can coexist with unsaved modified data; that is not a contradiction.

Important details and recovery

  1. Do not synchronize unwanted text merely to clear a warning. Preserve other work and deliberately reload the disk save if you intend to abandon edits.
  2. Do not use legacy JSON export or Save As to bypass the live-save gate. They are not substitutes for writing the retained NMS target.
  3. Processing is noncancellable; do not repeatedly trigger sync while it is still running.
