Organize stationary storage instead of carried storage.

Use case 38 · Working with inventories

Help Index → Working with inventories → Use case 38

Gather from stationary inventories while leaving mobile inventories out of the source selection. This example collects resources into Container 1 without expanding storage.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Load the intended save and confirm its active Main or Expedition context. Make a full backup before changing data.
  2. Only one tab can hold unsynced Raw JSON at a time: leaving a tab with a red sync light asks Sync, Abandon or Cancel. Sync and compare exact values. Invalid or refused text stops the sync with a message and keeps the light red; [] is applied on Bases, Starships and Teleport Endpoints and refused on Inventory by the count rule.
  3. Inventory Raw JSON can be synced or Pretty Printed if it keeps exactly the same inventories in the same order. Organizer and Replace Items from Backup remain the simpler tools for moves and replacement.

Steps

  1. Resolve each tab’s unsynced Raw JSON before leaving it: the app asks Sync, Abandon or Cancel. Sync and verify exact values. After a parse error or refusal the text stays and the light stays red; correct it and retry. Inventory Raw JSON must keep the same inventories in the same order. (control reference)
  2. If Inventory Organizer is not already open, choose Inventory Processing → Node View → Inventory Organizer before using the dialog controls below. (control reference)
  3. Click Stationary Storages. Check the available Containers, Fish Bait Box and Cooking Ingredients; ensure Exosuit, Freighter, Fish Platform and all starship source boxes are unchecked. (control reference)
  4. Keep Container 1 checked if you want the full stationary preset. Set Resources → Container 1 and every other category to Leave where they are. (control reference)
  5. Uncheck Overflow: if destination is full, overflow to other 'Container' type storages. Uncheck Expand all Destination storages to 120 cells. Only Container 1 may receive moved records, using its existing free cells. (control reference)
  6. Click Review Moves, inspect the stationary routes and apply only the wanted candidate with Apply To App Data. (control reference)

Expected result

  1. Resource records already in Container 1 stay there because their source and destination match. Eligible resource records from other checked stationary inventories can arrive if space exists.
  2. Mobile contents are not gathered. Whole stack quantities remain unchanged; records without room remain at their sources.

What changes, and when to save

Review Moves changes no inventory data. Apply To App Data publishes the reviewed candidate in memory, marks it modified and closes the dialog. File → Save is separate and writes the loaded save target. Organizer preferences persist even when Close cancels the proposal; neither a review nor preferences create a save backup. Before a live write, check that every intended edit is present.

Check the result

  1. Inspect Container 1, the other checked containers, Fish Bait Box and Cooking Ingredients after applying. Confirm mobile inventories did not receive an unintended destination assignment.

Important details and recovery

  1. Stationary Storages replaces the previous source selection; Fish Platform is mobile, not stationary.
  2. An unchecked mobile inventory would still be writable if assigned as a destination, which this example avoids.
  3. Do not interpret an absent retained-only review row as proof that every stationary resource moved.
