Replace an inventory’s items from a backup and understand what else changes.

Use case 48 · Working with inventories

Help Index → Working with inventories → Use case 48

Replace a selected inventory’s item records from an inventory backup without assuming that the backup restores all inventory metadata. A small target can also gain valid cells.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Load and confirm the intended save/context; make a full backup before replacing contents.
  2. Have a trusted inventory backup and a separate backup of the target’s current contents. Do not overwrite either recovery file.
  3. Only one tab can hold unsynced Raw JSON at a time: leaving a tab with a red sync light asks Sync, Abandon or Cancel. Sync and compare exact values. Invalid or refused text stops the sync with a message and keeps the light red; [] is applied on Bases, Starships and Teleport Endpoints and refused on Inventory by the count rule.
  4. Inventory Raw JSON can be synced or Pretty Printed if it keeps exactly the same inventories in the same order. Organizer and Replace Items from Backup remain the simpler tools for moves and replacement.
  5. Use a known complete inventory export with a Slots list; the filename extension does not validate structure. A replacement error can occur after ValidSlotIndices expanded but before Slots changed, so the target is not guaranteed unchanged.

Steps

  1. Resolve each tab’s unsynced Raw JSON before leaving it: the app asks Sync, Abandon or Cancel. Sync and verify exact values. After a parse error or refusal the text stays and the light stays red; correct it and retry. Inventory Raw JSON must keep the same inventories in the same order. (control reference)
  2. Open Inventory Processing → Node View and identify the target inventory. Use Backup this Inventory first to preserve the target’s present contents in a different file. (control reference)
  3. Right-click the inventory record itself and choose Replace Items from Backup. In Replace Inventory Contents, select the intended *.nms_inventory.json backup. (control reference)
  4. Confirm the file choice only when replacement is intended. This command does not offer Organizer-style Review Moves or Apply staging; cancel the file picker to avoid the replacement. (control reference)
  5. After either success or an error, inspect the target’s actual Slots and ValidSlotIndices before retrying or saving. Missing Slots can fail after capacity expands. Preserve useful work; if abandoning the replacement, deliberately reload the saved baseline. Do not retry or save blindly, even if the visible tree looks unchanged. (control reference)

Expected result

  1. The target’s Slots list is replaced with the backup’s Slots; this is not an additive import or a stack merge. Existing target items are displaced.
  2. If the target has fewer than 120 ValidSlotIndices entries, the helper resets that list to the 120-cell grid. The target’s Name and other inventory metadata are not replaced wholesale from the backup.

What changes, and when to save

Replacement changes the loaded app data, not the selected backup file or live save. File → Save is the separate live-save write. A one-inventory backup is not a full-save restore; if the replacement is unwanted, avoid saving it and reload the saved data deliberately. Compare every intended edit before any live write.

Check the result

  1. Compare the target’s new item IDs, amounts and positions with the intended backup. Check the target identity and valid-cell list, and inspect any error before File → Save.

Important details and recovery

  1. Organizer’s expansion checkbox does not control this separate replacement helper.
  2. This is not a full-save restore and does not restore every field of the exported inventory record.
  3. Keep the original backup intact. A success notice is not an item-level compatibility or in-game validation guarantee.
  4. Use a known complete inventory export with a Slots list; the filename extension does not validate structure. A replacement error can occur after ValidSlotIndices expanded but before Slots changed, so the target is not guaranteed unchanged. Preserve needed work and deliberately reload the saved baseline if abandoning the failed attempt.
