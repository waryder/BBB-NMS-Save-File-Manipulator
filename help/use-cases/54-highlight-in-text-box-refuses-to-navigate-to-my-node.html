Highlight In Text Box refuses to navigate to my node.

Use case 54 · When something does not behave as expected

Help Index → When something does not behave as expected → Use case 54

Highlight unavailable means the app cannot prove a reliable structural match between that node and the displayed JSON. It refuses rather than jumping to an arbitrary repeated word or silently repairing data.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Read and retain the complete refusal message. Do not save or edit values simply to dismiss a navigation problem.
  2. Resolve any unsynced Raw JSON first: leaving a tab with a red sync light asks Sync, Abandon or Cancel. Copying a node label is not a JSON backup.
  3. A parse error or refused text stops with a message, keeps your text and keeps the light red; [] is applied on Bases, Starships and Teleport Endpoints and refused on Inventory by the count rule. Verify actual values.
  4. Inventory Raw JSON can be synced if it keeps the same inventories in the same order. Organizer and Replace Items from Backup remain the simpler tools for moves and replacement.

Steps

  1. Dismiss Highlight unavailable and check whether Raw JSON was edited after the current Node View was built. Compare the intended change with the existing record; the previous cursor selection remains unchanged on refusal. (control reference)
  2. Correct the syntax, Sync to Node View, wait for Processing to dismiss, and verify the exact value in both panes. After a parse error the light stays red and your text is kept; correct it and retry. Inventory Raw JSON must keep the same inventories in the same order. (control reference)
  3. Select the node again in the freshly built tree, then retry Highlight In Text Box. Do not rely on an earlier selection after deletion, reordering or another tree change. (control reference)
  4. If refusal persists, inspect the message for unsupported, duplicate-key or unmapped structure. Use Search Text only as a manual inspection aid and check the surrounding record yourself; do not assume the first matching value identifies the node. (control reference)

Expected result

  1. Successful navigation uses the exact structural key/value location and selects its line, including when text formatting differs.
  2. On refusal, text, tree and save data remain unchanged. The app does not automatically synchronize, regenerate text or choose a guessed match.

What changes, and when to save

Highlighting itself is read-only. A deliberate synchronization can publish your text edits into app memory, but neither navigation nor synchronization writes the live save.

Check the result

  1. On success, check the selected field within the correct record, especially for repeated names and values. If a warning remains, preserve the text and seek help with the exact message rather than making speculative structural edits.

Important details and recovery

  1. A green sync indicator alone does not prove a reliable mapping or game-valid data.
  2. The same navigation refusal rules apply in bases, starships and inventories. Do not use Pretty Print to repair ambiguity.
