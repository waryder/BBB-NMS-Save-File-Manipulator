Remove an unwanted starship using the ship-specific deletion safeguards.

Use case 32 · Working with starships

Help Index → Working with starships → Use case 32

Use Delete Node on the complete Starships ownership record to invoke ship-specific deletion. Unlike generic base removal, this preserves fixed slot positions and performs the cleanup required by the selected ship category.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Keep a full-save backup; deleting a Corvette also removes its linked build.
  2. Load the correct context and identify at least one other occupied ship that must remain.
  3. Only one tab can hold unsynced Raw JSON at a time: leaving a tab with a red sync light asks Sync, Abandon or Cancel. Sync and compare exact values. Invalid or refused text stops the sync with a message and keeps the light red; [] is applied on Bases, Starships and Teleport Endpoints and refused on Inventory by the count rule.
  4. Inventory Raw JSON can be synced or Pretty Printed if it keeps exactly the same inventories in the same order. Organizer and Replace Items from Backup remain the simpler tools for moves and replacement.

Steps

  1. Resolve each tab’s unsynced Raw JSON before leaving it: the app asks Sync, Abandon or Cancel. Sync and verify exact values. After a parse error or refusal the text stays and the light stays red; correct it and retry. Inventory Raw JSON must keep the same inventories in the same order. (control reference)
  2. In Starships, identify the unwanted complete slot node using its position and resource identity; collapse its children to avoid selecting a nested field. (control reference)
  3. Right-click the whole slot and choose Delete Node. The request is validated before confirmation; a nested node alone is refused. (control reference)
  4. Review the Delete Nodes confirmation. Cancel if this is not the intended occupied ship, otherwise confirm. (control reference)
  5. Inspect the resulting empty slot, surviving roster, and any affected Bases records before saving. (control reference)

Expected result

  1. Ownership remains a twelve-entry array. The deleted position receives the appropriate empty ownership template and its legacy-colour flag resets; surviving ships keep their original positions.
  2. Custom-built ships also have their mapped appearance reset. Corvettes use their own empty template, reset mapped appearance, and lose their entire uniquely linked PlayerShipBase build. Ordinary ships do not have their appearance entry reset.
  3. If the deleted ship was PrimaryShip, selection moves to the lowest remaining occupied index. A CorvetteEditAssociatedShipIndex pointing at the deleted slot becomes -1; unrelated editor data remains.

What changes, and when to save

Changes stay in the loaded app data until File > Save NMS Save File writes the retained live slot and Main or Expedition context. Close No Man’s Sky and confirm that destination before saving; a green synchronization light alone does not mean the game file was saved. Before a live write, check that every intended edit is present.

Check the result

  1. Check the intended resource filename is now empty and every survivor remains at the same index.
  2. For a Corvette, confirm only its linked build disappeared; inspect the new primary selection when relevant.

Important details and recovery

  1. Deleting the last occupied ship is blocked. Missing or ambiguous Corvette builds, malformed linked data or stale selection refuse the request rather than falling back to generic removal. Deletion discards that ship’s equipment and cargo, not just its displayed name.
