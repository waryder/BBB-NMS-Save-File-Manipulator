Upgrade several starships in one operation.

Use case 27 · Working with starships

Help Index → Working with starships → Use case 27

Choose several ships in one Upgrade Starships operation and review each result independently. A successful ship does not make another selected ship’s rejection or skipped technology step a success.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Make a full backup and verify the active loaded context.
  2. Sync or abandon any unsynced Raw JSON before opening the picker; the operation will not silently synchronize text for you.
  3. Only one tab can hold unsynced Raw JSON at a time: when you leave a tab whose sync light is red, the app asks Sync, Abandon or Cancel. Resolve that tab before structured operations, which refuse while any tab is unsynced.
  4. Before opening Upgrade Starships, record each intended zero-based ownership index in the tree. Named picker checkboxes show no visible index: count ALL ownership-ordered rows from one, including unoccupied rows; tree index 0 is picker row 1. Cancel if you cannot identify the row confidently.

Steps

  1. Keep a copy of complex edits you cannot afford to retype. Invalid or refused text is never applied: the error is shown, the text stays and the light stays red. Inventory Raw JSON must keep the same inventories in the same order.
  2. In Starships, click Upgrade Starships and read the replacement/preservation warning. (control reference)
  3. Check the intended ownership-ordered rows by counting ALL rows from one, including unoccupied rows, against the zero-based tree indices recorded before opening. Named labels have no visible slot number; cancel if any row identity is uncertain. (control reference)
  4. Review the complete checked set, especially duplicate names and unnamed or unoccupied labels. Click Cancel if you need to inspect the roster first. (control reference)
  5. Click OK to apply the selection. After progress, read every row and the Upgrade notes section in the results, then close the report with OK. (control reference)

Expected result

  1. Selected ships are planned independently with matched reference families; rejected ships and unoccupied slots do not prevent other selected ships from receiving their permitted changes.
  2. Non-Corvette technology Slots are replaced wholesale on technology success. Corvettes retain existing equipment and builds and add only missing reference technology. Stats/class may still apply when technology is skipped.

What changes, and when to save

Changes stay in the loaded app data until File > Save NMS Save File writes the retained live slot and Main or Expedition context. Close No Man’s Sky and confirm that destination before saving; a green synchronization light alone does not mean the game file was saved. Compare the intended values before authorizing a live write.

Check the result

  1. Account for each selected slot as Upgraded, Already up to date, stats/class applied with tech skipped, Rejected, or unoccupied.
  2. Inspect unexpected outcomes and check unselected ships remain unchanged before deciding to save the combined result.

Important details and recovery

  1. The batch is not a promise of uniform success. Do not blindly repeat upgrades to cure a reference or layout error; read the per-ship reason first. A batch containing no actual changes does not create a new model edit.
