Make a small JSON edit and update the Node View.

Use case 12 · Working with Node View and Raw JSON

Help Index → Working with Node View and Raw JSON → Use case 12

Work one small Bases Raw JSON edit: change only the Name string of one identified base, then compare it before and after synchronization. This is an in-memory example, not proof that JSON syntax establishes game semantics; it is not an inventory-edit recipe.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Close No Man’s Sky, load the intended save and create a verified full backup before editing.
  2. Only one tab can hold unsynced Raw JSON at a time: when you leave a tab whose sync light is red, the app asks Sync, Abandon or Cancel. Resolve that tab before structured operations, which refuse while any tab is unsynced.
  3. Identify one base by its current Name and GalacticAddress. Record those values and keep its complete pre-edit record for comparison. A parse error or refused text stops the sync with a message and keeps the light red; an empty [] is applied on Bases, Starships and Teleport Endpoints and refused on Inventory by the count rule. Green means the text reached the app data; it does not prove game acceptance. Compare the exact value in both panes; correct and retry, or leave the tab and choose Abandon to reload the app data.

Steps

  1. Keep a copy of complex edits you cannot afford to retype. Invalid or refused text is never applied: the error is shown, the text stays and the light stays red. Inventory Raw JSON must keep the same inventories in the same order.
  2. Open Bases and identify the intended complete base by Name and GalacticAddress. Use Highlight In Text Box or Search Text to locate that record; do not choose an inventory or ship field. (control reference)
  3. In that base record only, change its Name string, for example from "Garden" to "Garden North" if that is your identified base’s original name. Keep quotes, string type and every other field/record unchanged; do not paste this example over the array. (control reference)
  4. Keep an external copy of the edited Bases text. Click Sync to Node View once and wait. If an error appears, your text stays and the light stays red; correct it and sync again. (control reference)
  5. Find the same base again using its unchanged GalacticAddress. Verify Name equals your chosen new string in both panes. Compare the complete before/after record and other base records; only the chosen Name should differ. (control reference)

Expected result

  1. For this nonempty Bases array, a successfully applied edit changes the selected base’s Name in the model and refreshed panes; verify the exact value, not just the light.
  2. A failed parse keeps the sync light red and Node View unchanged. Syntax success does not establish game-schema or game-acceptance validity.

What changes, and when to save

Text editing and synchronization change editor/model memory only. A separate confirmed File > Save NMS Save File is required to overwrite the loaded live data/metadata pair. Compare the intended values before authorizing a live write.

Check the result

  1. Compare the original and new Name, unchanged GalacticAddress and all neighboring fields/records. Confirm any other wanted edits were synced and verified before saving.

Important details and recovery

  1. JSON syntax validity is not game-schema or game-acceptance validation.
  2. If you want to abandon the edit instead, reload deliberately; do not save first.
  3. Inventory Raw JSON sync and Pretty Print replace each inventory’s contents in place. Keep exactly the same inventories in the same order; a changed count, an empty entry or [] is refused without changing data. Inspect actual Name and Slots before saving.
