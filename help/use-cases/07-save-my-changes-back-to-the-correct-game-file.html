Save my changes back to the correct game file.

Use case 7 · Opening, saving, and protecting your data

Help Index → Opening, saving, and protecting your data → Use case 7

File > Save NMS Save File writes the edited context back to the exact Auto or Manual file retained by the successful live load. It also updates that file’s matching metadata. It is not Save As and does not use a slot merely browsed afterward.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Close No Man’s Sky and keep a verified independent full backup.
  2. Load the intended live save first. Without a retained live source, the app’s legacy JSON-writing path is not a game save.
  3. Only one tab can hold unsynced Raw JSON at a time: when you leave a tab whose sync light is red, the app asks Sync, Abandon or Cancel. Resolve that tab before structured operations, which refuse while any tab is unsynced.
  4. A parse error or refused text stops the sync with a message and keeps the light red; an empty [] is applied on Bases, Starships and Teleport Endpoints and refused on Inventory by the count rule. Green means the text reached the app data; it does not prove game acceptance. Compare the exact value in both panes; correct and retry, or leave the tab and choose Abandon to reload the app data.

Steps

  1. Keep a copy of complex edits you cannot afford to retype. Invalid or refused text is never applied: the error is shown, the text stays and the light stays red. Inventory Raw JSON must keep the same inventories in the same order.
  2. Check the loaded-slot status and review the edits in each affected tab. (control reference)
  3. Sync each tab with wanted edits and verify the values; a failed or refused sync keeps its light red and blocks Save. Before Save, compare all intended values and untouched records with your copies; the save gate checks flags, not game-schema validity. (control reference)
  4. Choose File > Save NMS Save File. (control reference)
  5. Read Confirm Live Save Write. Confirm the slot and Main or Expedition context, and ensure the game is closed. Choose Cancel if anything is wrong; choose OK only to authorize the overwrite. (control reference)
  6. Wait for saving and verification to finish. Read the Live save written notice and its exact data and metadata paths. (control reference)

Expected result

  1. The selected context is merged into the retained full save while the inactive context and unrelated root fields are preserved.
  2. Only the retained selected data/metadata pair is replaced; the other Auto/Manual sibling is not updated. Successful verification establishes a new saved-data baseline.

What changes, and when to save

OK at the live-write confirmation authorizes a real live-file overwrite. Synchronizing alone changes app memory. Cancel leaves current edits and live files unchanged. Compare the intended values before authorizing a live write.

Check the result

  1. Require the Saved and verified notice and check both target paths.
  2. Confirm Modified Data Saved is green. Inspect the intended edit again; an encoded, verified file is not proof the game will accept every edited value.

Important details and recovery

  1. There is no continuous external-file conflict detection. Keep the game and other save writers closed.
  2. The pair is not power-loss atomic. If recovery fails, keep the game closed and use independent recovery guidance rather than retrying blindly.
  3. Inventory Raw JSON sync and Pretty Print replace each inventory’s contents in place. Keep exactly the same inventories in the same order; a changed count, an empty entry or [] is refused without changing data. Inspect actual Name and Slots before saving.
