Add a previously backed-up base to the loaded save.

Use case 22 · Working with bases

Help Index → Working with bases → Use case 22

Add a base-backup record to the currently loaded save context. Restore a Base is an insertion command: it does not search for and replace an older matching base.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Load the intended destination save and verify Main or Expedition.
  2. Keep a full backup of that destination and locate a trusted single-base .nms_base.json file. Synchronize pending text edits before restoring.
  3. Only one tab can hold unsynced Raw JSON at a time: when you leave a tab whose sync light is red, the app asks Sync, Abandon or Cancel. Resolve that tab before structured operations, which refuse while any tab is unsynced.

Steps

  1. Keep a copy of complex edits you cannot afford to retype. Invalid or refused text is never applied: the error is shown, the text stays and the light stays red. Inventory Raw JSON must keep the same inventories in the same order.
  2. Open Bases and right-click the top-level array root, not a named base or one of its child fields. (control reference)
  3. Choose Restore a Base. The file dialog is titled Restore A Base To First Position In Tree. (control reference)
  4. Select the single-base backup file and open it. Wait for New Base Added To Tree and the refreshed list. (control reference)
  5. Inspect the newly inserted first base and compare its label and Raw JSON with the record you meant to add. (control reference)

Expected result

  1. The selected JSON record is inserted at index zero of PersistentPlayerBases in app memory. Previously loaded bases move down one position.
  2. An existing record with the same name or address remains present. Restoring the same file twice adds it twice; this is not a merge or duplicate-aware recovery.

What changes, and when to save

Changes stay in the loaded app data until File > Save NMS Save File writes the retained live slot and Main or Expedition context. Close No Man’s Sky and confirm that destination before saving; a green synchronization light alone does not mean the game file was saved. Compare the intended values before authorizing a live write.

Check the result

  1. Confirm the base count increased by one and that the first record has the expected address and Objects count.
  2. Review any apparent duplicate before saving; choose deliberately whether either record should be removed.

Important details and recovery

  1. Use a complete single-base backup, not an inventory backup or full-context export. Successful JSON loading and insertion do not establish game-valid ownership, construction relationships or destination compatibility.
