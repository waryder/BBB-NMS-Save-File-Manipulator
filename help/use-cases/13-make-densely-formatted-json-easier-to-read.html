Use case 13 · Working with Node View and Raw JSON

Help Index → Working with Node View and Raw JSON → Use case 13

Pretty Print reads the current editor into the model and reloads indented text; it is not read-only formatting. It works on all four tabs; on Inventory the text must keep the same inventories in the same order.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Load the intended save and open the tab whose Raw JSON is hard to read.
  2. Review any pending text edits before formatting. Keep a separate copy of text you cannot afford to lose, especially if it may contain a syntax error.
  3. Only one tab can hold unsynced Raw JSON at a time: when you leave a tab whose sync light is red, the app asks Sync, Abandon or Cancel. Resolve that tab before structured operations, which refuse while any tab is unsynced.
  4. A parse error or refused text stops the sync with a message and keeps the light red; an empty [] is applied on Bases, Starships and Teleport Endpoints and refused on Inventory by the count rule. Green means the text reached the app data; it does not prove game acceptance. Compare the exact value in both panes; correct and retry, or leave the tab and choose Abandon to reload the app data.

Steps

  1. Keep a copy of complex edits you cannot afford to retype. Invalid or refused text is never applied: the error is shown, the text stays and the light stays red. Inventory Raw JSON must keep the same inventories in the same order.
  2. Inspect the Raw JSON text and synchronization light. Decide whether pending edits are intentional before continuing. (control reference)
  3. If the text contains an unfinished or unwanted change, finish correcting it or deliberately reload saved data instead of treating Pretty Print as a repair tool. (control reference)
  4. With the intended values reviewed, click Pretty Print. (control reference)
  5. Inspect the resulting indentation, line breaks and rebuilt Node View. The formatter serializes the model’s data with four-space indentation. (control reference)
  6. If parsing reports an error, stop and compare the displayed text with your preserved copy. Correct the error before formatting or synchronizing again. (control reference)
  7. Use Search Text or Highlight In Text Box to relocate the field you were inspecting after reformatting. (control reference)

Expected result

  1. With successfully applied text, the editor is indented and Node View refreshes from the model; compare actual values to verify that condition.
  2. On Inventory Processing, Pretty Print is refused with a message if the text no longer has the same inventories in the same order; nothing changes.

What changes, and when to save

Pretty Print can update editor text and app memory. It does not write a game file, create a backup, or mark a verified live save complete. Compare the intended values before authorizing a live write.

Check the result

  1. Check that the intended values and containing records are still present, not just that the text looks neater.
  2. Check the tab synchronization light and Modified Data Saved separately; a formatting-related editor event may conservatively mark the session changed.

Important details and recovery

  1. Pretty Print does not repair invalid JSON: it shows the parse error and stops, leaving your text unchanged and the light red.
  2. Indentation does not establish that the game supports the data.
  3. Inventory Raw JSON sync and Pretty Print replace each inventory’s contents in place. Keep exactly the same inventories in the same order; a changed count, an empty entry or [] is refused without changing data. Inspect actual Name and Slots before saving.
