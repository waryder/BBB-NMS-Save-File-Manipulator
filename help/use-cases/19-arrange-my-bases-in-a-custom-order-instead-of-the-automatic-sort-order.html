Arrange my bases in a custom order instead of the automatic sort order.

Use case 19 · Working with bases

Help Index → Working with bases → Use case 19

Reorder complete base records manually in Bases Node View when the automatic grouping is not the order you want. Work at the base-list level, not inside an individual base’s fields or construction objects.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Keep a full backup and load the correct Main or Expedition context.
  2. Synchronize pending Raw JSON edits before moving nodes.
  3. Only one tab can hold unsynced Raw JSON at a time: when you leave a tab whose sync light is red, the app asks Sync, Abandon or Cancel. Resolve that tab before structured operations, which refuse while any tab is unsynced.

Steps

  1. Keep a copy of complex edits you cannot afford to retype. Invalid or refused text is never applied: the error is shown, the text stays and the light stays red. Inventory Raw JSON must keep the same inventories in the same order.
  2. Expand the base-list root enough to see each base label, then collapse the individual bases so their child fields are out of the way. (control reference)
  3. Use the left mouse button to drag one complete base onto another complete base under the same list root. Do not use right-drag, which selects a deletion range. (control reference)
  4. Release, let the tree and Raw JSON refresh, and inspect the actual resulting position. Repeat small moves until the order is correct. (control reference)
  5. Leave Sort By Gal, Sys, Name alone once your custom order is finished; another automatic sort will replace that order. (control reference)

Expected result

  1. Accepted drops remove and reinsert the complete record and publish the revised list to app memory. Positions and labels are refreshed.
  2. The generic drop handler requires compatible array/dictionary parents and refuses to drag a node whose parent has only one child.

What changes, and when to save

Changes stay in the loaded app data until File > Save NMS Save File writes the retained live slot and Main or Expedition context. Close No Man’s Sky and confirm that destination before saving; a green synchronization light alone does not mean the game file was saved. Compare the intended values before authorizing a live write.

Check the result

  1. Check the entire resulting base sequence, not just the dragged label.
  2. Check base count, addresses and part counts against the records you intended to preserve.

Important details and recovery

  1. Parent-type checks are structural checks, not game-side validation. Do not drag nested fields between records or apply this workflow to starships: safe ship reorder associations are not established.
