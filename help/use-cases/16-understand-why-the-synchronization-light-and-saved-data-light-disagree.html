Use case 16 · Working with Node View and Raw JSON

Help Index → Working with Node View and Raw JSON → Use case 16

Raw JSON’s light reports tab synchronization to Node View. Modified Data Saved tracks edits since live load or verified save. Live Save Loaded reports retained live-source identity, not whether edits are saved.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Compare labels, not colors alone. Do not type or save merely to test indicators.
  2. Use a successfully loaded live save when comparing normal loaded-state behavior.
  3. Only one tab can hold unsynced Raw JSON at a time: when you leave a tab whose sync light is red, the app asks Sync, Abandon or Cancel. Resolve that tab before structured operations, which refuse while any tab is unsynced.
  4. A parse error or refused text stops the sync with a message and keeps the light red; an empty [] is applied on Bases, Starships and Teleport Endpoints and refused on Inventory by the count rule. Green means the text reached the app data; it does not prove game acceptance. Compare the exact value in both panes; correct and retry, or leave the tab and choose Abandon to reload the app data.

Steps

  1. Keep a copy of complex edits you cannot afford to retype. Invalid or refused text is never applied: the error is shown, the text stays and the light stays red. Inventory Raw JSON must keep the same inventories in the same order.
  2. Read Live Save Loaded in the main status area. Green means a live save is loaded or has been saved live; it can remain green while edits are unsaved. (control reference)
  3. Read Modified Data Saved. Green means no changes have been recorded since the live-load or verified-save baseline. It is not a continuous comparison against the disk. (control reference)
  4. Inspect the Raw JSON synchronization light in each tab with pending work. A red tab light means its text has not been synchronized to Node View. (control reference)
  5. For wanted text, sync the tab and inspect the exact intended values. A green sync light with red Modified Data Saved is normal: the edit is in app data but not yet saved to the game file. (control reference)
  6. Only if you intend to commit the edits, use File > Save NMS Save File, confirm the correct slot/context and require the verified success notice. Otherwise leave the edits in memory or discard them by deliberately reloading. (control reference)

Expected result

  1. Synchronization can turn the tab light green while the saved-data light remains red.
  2. Formatting and editor events can conservatively record changes even when you believe only whitespace changed. No live source also prevents a green saved baseline.

What changes, and when to save

Inspecting lights writes nothing. Sync changes app memory. Only separately confirmed live saving writes game files; clipboard export and full backup do not clear unsaved editor status. Compare the intended values before authorizing a live write.

Check the result

  1. Check the intended data as well as the lights. A green sync light is not a game-schema validation result.
  2. After a successful live load or verified live save, confirm the expected baseline indication; do not use it to infer that external programs have left the files unchanged.

Important details and recovery

  1. External changes are not continuously monitored. Keep the game and other save writers closed.
  2. Green saved status is not proof of game acceptance or a substitute for an independent backup.
  3. Inventory Raw JSON sync and Pretty Print replace each inventory’s contents in place. Keep exactly the same inventories in the same order; a changed count, an empty entry or [] is refused without changing data. Inspect actual Name and Slots before saving.
