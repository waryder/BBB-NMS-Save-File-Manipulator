Use case 44 · Working with inventories

Help Index → Working with inventories → Use case 44

Regenerate the proposal after changing a destination. The Organizer deliberately disables Apply when the current choices no longer match the reviewed candidate.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Load the intended save and confirm its active Main or Expedition context. Make a full backup before changing data.
  2. Only one tab can hold unsynced Raw JSON at a time: leaving a tab with a red sync light asks Sync, Abandon or Cancel. Sync and compare exact values. Invalid or refused text stops the sync with a message and keeps the light red; [] is applied on Bases, Starships and Teleport Endpoints and refused on Inventory by the count rule.
  3. Inventory Raw JSON can be synced or Pretty Printed if it keeps exactly the same inventories in the same order. Organizer and Replace Items from Backup remain the simpler tools for moves and replacement.

Steps

  1. Resolve each tab’s unsynced Raw JSON before leaving it: the app asks Sync, Abandon or Cancel. Sync and verify exact values. After a parse error or refusal the text stays and the light stays red; correct it and retry. Inventory Raw JSON must keep the same inventories in the same order. (control reference)
  2. If Inventory Organizer is not already open, choose Inventory Processing → Node View → Inventory Organizer before using the dialog controls below. (control reference)
  3. Click Clear and check only Exosuit. Set Resources → Container 1 and all five other categories to Leave where they are. Uncheck both Optional checkboxes. (control reference)
  4. Click Review Moves and inspect the proposed route to Container 1. Do not apply it yet. (control reference)
  5. Change Resources to Container 2. Confirm Apply To App Data is disabled; the displayed live route no longer carries the old proposal’s calculated counts. (control reference)
  6. Recheck that Overflow: if destination is full, overflow to other 'Container' type storages. and Expand all Destination storages to 120 cells. are both unchecked. Click Review Moves again and inspect the new candidate. (control reference)
  7. Choose Apply To App Data only for the newly reviewed Container 2 proposal, or Close to leave app inventory data unchanged. (control reference)

Expected result

  1. A choice change discards the prior candidate. Apply cannot silently reuse the Container 1 proposal or re-plan behind the review screen.
  2. Source checkbox changes and optional-flag changes also invalidate review. A no-change replacement proposal leaves Apply disabled.

What changes, and when to save

Review Moves changes no inventory data. Apply To App Data publishes the reviewed candidate in memory, marks it modified and closes the dialog. File → Save is separate and writes the loaded save target. Organizer preferences persist even when Close cancels the proposal; neither a review nor preferences create a save backup. Compare every intended edit before any live write.

Check the result

  1. After applying, inspect Exosuit and Container 2. Check Container 1 to confirm it was not written by the abandoned first proposal before saving.

Important details and recovery

  1. Changed loaded data or save-source identity can cause Apply to refuse a stale candidate even if the dialog choices look unchanged; review again rather than forcing it.
  2. Regenerating a proposal does not save the game. Preferences may already reflect the new destination even if you close without applying.
