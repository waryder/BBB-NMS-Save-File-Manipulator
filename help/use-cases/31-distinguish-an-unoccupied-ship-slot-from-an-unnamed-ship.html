Distinguish an unoccupied ship slot from an unnamed ship.

Use case 31 · Working with starships

Help Index → Working with starships → Use case 31

An empty name does not make a ship slot unoccupied. The upgrade workflow checks Resource.Filename, while the ordinary Starships tree uses a name fallback that can look similar for occupied and empty records.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Load the intended save context and synchronize pending Starships text.
  2. Use the slot position as well as the displayed name when comparing tree rows with upgrade labels.
  3. Only one tab can hold unsynced Raw JSON at a time: when you leave a tab whose sync light is red, the app asks Sync, Abandon or Cancel. Resolve that tab before structured operations, which refuse while any tab is unsynced.
  4. Before opening Upgrade Starships, record each intended zero-based ownership index in the tree. Named picker checkboxes show no visible index: count ALL ownership-ordered rows from one, including unoccupied rows; tree index 0 is picker row 1. Cancel if you cannot identify the row confidently.

Steps

  1. Keep a copy of complex edits you cannot afford to retype. Invalid or refused text is never applied: the error is shown, the text stays and the light stays red. Inventory Raw JSON must keep the same inventories in the same order.
  2. Open Starships and locate the complete ownership row. Read its zero-based bracketed position; the display also uses a one-based Starship number. (control reference)
  3. Expand or highlight the record and inspect Resource.Filename rather than deciding from Name or a seed value. (control reference)
  4. Open Upgrade Starships to see the picker’s occupancy-aware labels. An empty or absent resource filename gives Slot X - (unoccupied); an occupied ship with a blank name gets Starship X (unnamed). (control reference)
  5. Click Cancel if you were only identifying the slot. If you deliberately run an upgrade including it, read the corresponding result label. (control reference)

Expected result

  1. A named record with an empty resource filename is still treated as unoccupied by the upgrade workflow. A ship with a real resource filename and no name remains an occupied upgrade candidate.
  2. The normal tree may show No name provided rather than the picker’s explicit occupancy label. Unoccupied selections are preserved and reported separately; unnamed supported ships can be upgraded.

What changes, and when to save

Reading labels and cancelling the picker do not change app data or game files. An actual upgrade changes app memory only; File > Save NMS Save File is a separate confirmed write. Compare the intended values before authorizing a live write.

Check the result

  1. Match one-based picker/result numbers to the correct zero-based array position before acting.
  2. Treat malformed resource structures as an error to investigate, not as reliable proof of an empty slot.

Important details and recovery

  1. Neither stale Name nor seed fields establish occupancy. Safe deletion requires a valid twelve-slot roster and valid resource structure; it is not a general repair tool for malformed ownership data.
