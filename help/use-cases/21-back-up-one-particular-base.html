Back up one particular base.

Use case 21 · Working with bases

Help Index → Working with bases → Use case 21

Export one complete base as a reusable base-backup file without exporting the entire save. The backup captures that record from the current tree, including any synchronized edits already made in the app.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Identify the intended base by name, galaxy, system and part count.
  2. Synchronize pending Bases Raw JSON edits first if you want those edits included. A full-save backup is still separate protection.
  3. Only one tab can hold unsynced Raw JSON at a time: when you leave a tab whose sync light is red, the app asks Sync, Abandon or Cancel. Resolve that tab before structured operations, which refuse while any tab is unsynced.

Steps

  1. Keep a copy of complex edits you cannot afford to retype. Invalid or refused text is never applied: the error is shown, the text stays and the light stays red. Inventory Raw JSON must keep the same inventories in the same order.
  2. Open Bases and locate the complete labeled base record directly under the list root. (control reference)
  3. Right-click that base label and choose Backup a Base. If the command is missing, click the whole base rather than a nested field or the list root. (control reference)
  4. Choose a distinct filename and folder in Save File. Use the NMS Base Files format, normally ending in .nms_base.json, and avoid overwriting your only earlier copy. (control reference)
  5. Complete the file dialog and check for File saved successfully. Retain the chosen path for a later restore. (control reference)

Expected result

  1. The app writes one JSON object representing the selected base to the chosen file. It does not export the full PersistentPlayerBases array or the whole loaded context.
  2. An empty base name uses default as the proposed filename stem; that stem does not identify the base for you.

What changes, and when to save

Backup a Base writes the separate backup file immediately. It neither saves your current app edits into the live game file nor creates a complete live-save recovery backup. Compare the intended values before authorizing a live write.

Check the result

  1. Check the destination and filename you chose, especially for unnamed or identically named bases.
  2. Confirm the source base is still present with the same position and Parts value.

Important details and recovery

  1. The export includes the saved record as it stands; it does not sanitize ownership, coordinates or linked relationships for another account. A write error is not a completed backup.
