My JSON will not synchronize—locate and correct the editing error.

Use case 55 · When something does not behave as expected

Help Index → When something does not behave as expected → Use case 55

Investigate a Raw JSON error: a failed or refused sync shows its reason, keeps your text and leaves the light red. This correction recipe applies to all four tabs; Inventory text must keep the same inventories in the same order.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Resolve any unsynced Raw JSON first: leaving a tab with a red sync light asks Sync, Abandon or Cancel. Record the exact error and affected tab.
  2. Keep your independent pre-edit backup. A new full backup captures disk files, not the unsynchronized text currently visible in the editor.
  3. A parse error or refused text stops with a message, keeps your text and keeps the light red; [] is applied on Bases, Starships and Teleport Endpoints and refused on Inventory by the count rule. Verify actual values.
  4. Inventory Raw JSON can be synced if it keeps the same inventories in the same order. Organizer and Replace Items from Backup remain the simpler tools for moves and replacement.

Steps

  1. Inspect the parse-error location and preceding line using Raw JSON’s line numbers and horizontal scrollbar. A missing delimiter can be reported after the mistake. (control reference)
  2. Compare the edited fragment with your known-good version. Correct only the understood error: check double-quoted keys and strings, commas between members, matching braces/brackets and accidentally pasted extra text. Preserve the surrounding record structure. (control reference)
  3. Correct the text and choose Sync to Node View in that tab. Wait for Processing to dismiss; it has no Cancel and Escape does not stop it. A remaining parse error is reported again and the light stays red; [] is applied on Bases, Starships and Teleport Endpoints and refused on Inventory by the count rule. Pretty Print reports the same error and leaves the text unchanged. (control reference)
  4. Compare the exact intended value, surrounding structure and identity in Node View and Raw JSON with the preserved copy. If any parse error or mismatch remains, do not save. Preserve useful work and deliberately reload the saved baseline if abandoning the edit. (control reference)

Expected result

  1. An edit reaches app memory only when its sync succeeds; verify the exact intended values.
  2. A status light or formatting change is not a substitute for checking that the intended value actually survived synchronization.

What changes, and when to save

Synchronization updates app memory, not the live file. A failed or refused sync keeps the light red and blocks Save. File → Save is a separate decision after exact-value review.

Check the result

  1. Compare each intended edit with its external copy, including other panes that may have refreshed. Green status means the text reached the app data; check the intended values before saving.

Important details and recovery

  1. Pretty Print is not automatic error correction or game-schema validation; on invalid or refused text it stops and leaves your text unchanged.
  2. Text Undo is an editor action, not an undo-all mechanism for tree operations or earlier live writes. Use a deliberate reload or manual backup recovery when appropriate.
