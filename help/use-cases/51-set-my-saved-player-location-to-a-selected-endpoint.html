Set my saved player location to a selected endpoint.

Use case 51 · Working with teleport endpoints

Help Index → Working with teleport endpoints → Use case 51

Stage a player-location change using one endpoint already stored in the active context. This edits saved-location data in the app; it does not teleport a running game.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Keep NMS closed, load the intended live save and confirm its active Main or Expedition context. Make a full backup before changing the location.
  2. Inspect the endpoint’s address and coordinates; do not proceed if the destination is uncertain.
  3. Only one tab can hold unsynced Raw JSON at a time: leaving a tab with a red sync light asks Sync, Abandon or Cancel. Sync and compare exact values. Invalid or refused text stops the sync with a message and keeps the light red; [] is applied on Bases, Starships and Teleport Endpoints and refused on Inventory by the count rule.
  4. Inventory Raw JSON can be synced or Pretty Printed if it keeps exactly the same inventories in the same order. Organizer and Replace Items from Backup remain the simpler tools for moves and replacement.

Steps

  1. Resolve each tab’s unsynced Raw JSON before leaving it: the app asks Sync, Abandon or Cancel. Sync and verify exact values. After a parse error or refusal the text stays and the light stays red; correct it and retry. Inventory Raw JSON must keep the same inventories in the same order. (control reference)
  2. Open Teleport Endpoints. Expand the outer array and identify the complete endpoint record you intend to use, checking its label, UniverseAddress and Position rather than selecting a similarly named entry. (control reference)
  3. Right-click that complete record directly beneath the array, not the array root or a child field. Choose Set Player Location to this Endpoint. This command immediately changes the in-memory location; it is not a preview dialog. (control reference)
  4. Read and dismiss the Set Player Location message. Treat Player has been moved as an app-data result, not confirmation of disk saving or a safe in-game spawn. (control reference)
  5. Review the intended change before choosing File → Save. Check the confirmation’s slot and Main or Expedition context; cancel if wrong. The later Live save written result reports the exact verified data and metadata paths. (control reference)

Expected result

  1. The active context receives the endpoint’s UniverseAddress and its three Position coordinates in the player/spawn location fields. LastKnownPlayerState becomes OnFoot.
  2. The endpoint list itself is not a new in-game teleport service. The command does not add a terrain-clearance offset.

What changes, and when to save

The context-menu command stages changes in app memory. Only a separately confirmed File → Save writes the loaded live target; keep the independent backup until the result is checked.

Check the result

  1. Confirm the endpoint you selected still has the address and three coordinates you intended. For a full-context comparison, inspect an exported context separately; the endpoint pane alone does not display all changed player/spawn fields.

Important details and recovery

  1. The app does not validate terrain or promise a safe arrival. Do not save an untrusted location.
  2. If the result is unwanted, preserve any other work you need and deliberately reload the disk save instead of assuming text Undo reverses this action.
