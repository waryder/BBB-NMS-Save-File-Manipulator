Reuse my remembered inventory-organization settings.

Use case 49 · Working with inventories

Help Index → Working with inventories → Use case 49

Reuse Organizer choices without confusing preferences with applied inventory changes. Reopening restores choices, not a reviewed candidate.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Load the intended save and confirm its active Main or Expedition context. Make a full backup before changing data.
  2. Only one tab can hold unsynced Raw JSON at a time: leaving a tab with a red sync light asks Sync, Abandon or Cancel. Sync and compare exact values. Invalid or refused text stops the sync with a message and keeps the light red; [] is applied on Bases, Starships and Teleport Endpoints and refused on Inventory by the count rule.
  3. Inventory Raw JSON can be synced or Pretty Printed if it keeps exactly the same inventories in the same order. Organizer and Replace Items from Backup remain the simpler tools for moves and replacement.

Steps

  1. Resolve each tab’s unsynced Raw JSON before leaving it: the app asks Sync, Abandon or Cancel. Sync and verify exact values. After a parse error or refusal the text stays and the light stays red; correct it and retry. Inventory Raw JSON must keep the same inventories in the same order. (control reference)
  2. Open Inventory Processing → Node View → Inventory Organizer and inspect the restored source checkboxes, six category routes and both Optional flags before reviewing. (control reference)
  3. For a reusable resource-only setup, click Clear and check Exosuit only. Set Resources → Container 1 and the five other categories to Leave where they are. (control reference)
  4. Uncheck Overflow: if destination is full, overflow to other 'Container' type storages. Uncheck Expand all Destination storages to 120 cells. Click Close without applying to keep this setup while leaving inventory data unchanged. (control reference)
  5. Reopen Organizer and check the remembered choices against the current inventory labels. Click Review Moves to create a fresh candidate, then Apply To App Data only if wanted. (control reference)

Expected result

  1. Source checks, category routes, overflow and expansion are remembered independently of File → Save. Choices are persisted as they change and when the dialog closes.
  2. Available inventories are matched by stable data paths, not display names or filtered row numbers. A saved destination unavailable in the current context displays Leave where they are.

What changes, and when to save

Review Moves is private. Apply publishes the candidate in memory, marks modified and closes. File → Save separately writes the loaded target. Closing retains preferences without applying data; preferences are not a backup. Compare every intended edit before any live write.

Check the result

  1. On reopening, verify every source and destination for the currently loaded context. Confirm Apply remains unavailable until a new review proposes a change. Inspect actual inventory contents after any Apply.

Important details and recovery

  1. Close, Escape and window-close cancel the data candidate but still persist preferences. Preferences are not an inventory backup.
  2. Unavailable saved identities are retained for reuse; a path can refer to a different currently loaded ship after save changes, so check the loaded labels.
  3. A settings-write warning means persistence was not confirmed. Sorter has separate remembered choices; its overflow checkbox initially defaults on rather than following Organizer preferences.
