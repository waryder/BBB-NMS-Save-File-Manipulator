Use spare containers when the assigned destination fills up.

Use case 40 · Working with inventories

Help Index → Working with inventories → Use case 40

Allow spare containers to receive resource records when Container 1 has no remaining cells, while keeping existing inventory capacities unchanged.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Load the intended save and confirm its active Main or Expedition context. Make a full backup before changing data.
  2. Only one tab can hold unsynced Raw JSON at a time: leaving a tab with a red sync light asks Sync, Abandon or Cancel. Sync and compare exact values. Invalid or refused text stops the sync with a message and keeps the light red; [] is applied on Bases, Starships and Teleport Endpoints and refused on Inventory by the count rule.
  3. Inventory Raw JSON can be synced or Pretty Printed if it keeps exactly the same inventories in the same order. Organizer and Replace Items from Backup remain the simpler tools for moves and replacement.

Steps

  1. Resolve each tab’s unsynced Raw JSON before leaving it: the app asks Sync, Abandon or Cancel. Sync and verify exact values. After a parse error or refusal the text stays and the light stays red; correct it and retry. Inventory Raw JSON must keep the same inventories in the same order. (control reference)
  2. If Inventory Organizer is not already open, choose Inventory Processing → Node View → Inventory Organizer before using the dialog controls below. (control reference)
  3. Click Clear and check only Exosuit. Keep every Container, Freighter, Fish Platform, Fish Bait Box, Cooking Ingredients and ship source unchecked. (control reference)
  4. Set Resources → Container 1. Set Crafted products, Technology, Consumables, Trade goods and Special items to Leave where they are, leaving Containers 2–10 unassigned. (control reference)
  5. Check Overflow: if destination is full, overflow to other 'Container' type storages. Uncheck Expand all Destination storages to 120 cells. This permits spare containers but forbids their automatic expansion. (control reference)
  6. Click Review Moves. Read visible destination and overflow counts, then Apply To App Data only if writes to spare containers are acceptable. (control reference)

Expected result

  1. The planner tries Container 1 first, then available unassigned containers backward from Container 10 toward Container 1. It skips any container assigned to any category and excludes the record’s source.
  2. If neither the assigned destination nor eligible spare containers have room, the whole record stays in Exosuit.

What changes, and when to save

Review Moves changes no inventory data. Apply To App Data publishes the reviewed candidate in memory, marks it modified and closes the dialog. File → Save is separate and writes the loaded save target. Organizer preferences persist even when Close cancels the proposal; neither a review nor preferences create a save backup. Before a live write, check that every intended edit is present.

Check the result

  1. Inspect Exosuit, Container 1 and eligible spare containers after applying. A row containing only overflow moves may be hidden even though the candidate changes data.

Important details and recovery

  1. Unchecked source boxes do not protect containers from receiving overflow.
  2. If expansion is later checked, all assigned destinations expand, and a spare container expands only when receiving a record.
  3. A category routed to its own source remains there; it does not overflow.
