Understand whether I’m editing my main game or expedition.

Use case 4 · Opening, saving, and protecting your data

Help Index → Opening, saving, and protecting your data → Use case 4

The app edits one context from the loaded save. Main maps to BaseContext and Season maps to ExpeditionContext according to the decoded ActiveContext marker. There is no visible context selector for switching between them.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Load the intended live save and retain its slot/account identity.
  2. Keep No Man’s Sky closed. Do not edit JSON or save simply to test which context is active.
  3. Only one tab can hold unsynced Raw JSON at a time: when you leave a tab whose sync light is red, the app asks Sync, Abandon or Cancel. Resolve that tab before structured operations, which refuse while any tab is unsynced.

Steps

  1. Keep a copy of complex edits you cannot afford to retype. Invalid or refused text is never applied: the error is shown, the text stays and the light stays red. Inventory Raw JSON must keep the same inventories in the same order.
  2. Inspect recognizable bases, ships or inventories in the loaded tabs. These are views of the context chosen at load time, not separate Main and Expedition workspaces. (control reference)
  3. For another read-only inspection, choose Tools > Export 'BaseContext' JSON to Clipboard and paste into a separate inspection tool. Check recognizable context contents there. (control reference)
  4. Treat the export label as a fixed menu name: for a Season load, it exports the loaded Expedition context, not the inactive Main context. (control reference)
  5. If you need an explicit Main/Expedition confirmation, invoke File > Save NMS Save File only with all tabs synchronized, read the slot and context in Confirm Live Save Write, then choose Cancel. (control reference)
  6. If the identity is not what you intended, stop and reopen the appropriate save. Do not try to change context by altering a tab’s JSON. (control reference)

Expected result

  1. Main selects BaseContext; Season selects ExpeditionContext. An absent marker is accepted as legacy Main-only only when ExpeditionContext is absent.
  2. Unsupported or ambiguous markers and invalid selected contexts are rejected rather than silently falling back to another branch.

What changes, and when to save

Inspection changes no live files. Export replaces clipboard text. Canceling save confirmation writes nothing. A real confirmed save writes edits only into the context retained at load. Compare the intended values before authorizing a live write.

Check the result

  1. Use the confirmation’s context name with recognizable loaded content; names alone can be similar across contexts.
  2. Cancel the save warning during inspection; no save success notice should appear.

Important details and recovery

  1. The context export is not the entire decoded save wrapper and does not include both contexts.
  2. There is no UI operation here to activate or convert an expedition.
