Upgrade one selected starship while leaving the others alone.

Use case 26 · Working with starships

Help Index → Working with starships → Use case 26

Upgrade one ship through the checkbox picker rather than assuming a selected tree row determines the target. The other ownership records are not included unless you check them in the dialog.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Keep a full backup and confirm the loaded slot and Main or Expedition context.
  2. Sync or abandon any unsynced Raw JSON first. Upgrade preflight checks all editing tabs, not just Starships.
  3. Only one tab can hold unsynced Raw JSON at a time: when you leave a tab whose sync light is red, the app asks Sync, Abandon or Cancel. Resolve that tab before structured operations, which refuse while any tab is unsynced.
  4. Before opening Upgrade Starships, record each intended zero-based ownership index in the tree. Named picker checkboxes show no visible index: count ALL ownership-ordered rows from one, including unoccupied rows; tree index 0 is picker row 1. Cancel if you cannot identify the row confidently.

Steps

  1. Keep a copy of complex edits you cannot afford to retype. Invalid or refused text is never applied: the error is shown, the text stays and the light stays red. Inventory Raw JSON must keep the same inventories in the same order.
  2. Open Starships and click Upgrade Starships. (control reference)
  3. Read the warning: non-Corvette technology items are replaced by the matched reference; Corvette equipment and build parts are preserved with missing-only additions. (control reference)
  4. Check only the intended ownership-ordered row identified before opening: count from one, including ALL unoccupied rows. The named checkbox does not display its slot index; duplicate names can be identical. Cancel if uncertain. All boxes start unchecked and tree selection is not picker selection. (control reference)
  5. Click OK, wait for progress to finish, then read that ship’s outcome and any notes in Starship Upgrade Results. (control reference)

Expected result

  1. A supported selected ship receives validated reference base statistics and S-class settings. Successful technology processing targets sixty enabled tech cells.
  2. A technology/capacity problem can produce stats/class applied with tech skipped. An unsupported model or invalid stats/class reference rejects that ship without changing it.

What changes, and when to save

Changes stay in the loaded app data until File > Save NMS Save File writes the retained live slot and Main or Expedition context. Close No Man’s Sky and confirm that destination before saving; a green synchronization light alone does not mean the game file was saved. Compare the intended values before authorizing a live write.

Check the result

  1. Inspect the selected ship’s class, statistics and technology, not just the completion popup.
  2. Verify the unchecked ships retain their prior identities, equipment and cargo.

Important details and recovery

  1. For non-Corvettes, extras, trails, figurines and module seeds in technology Slots may be lost in reference replacement. Cancel or OK with nothing checked performs no upgrade and produces no results dialog.
