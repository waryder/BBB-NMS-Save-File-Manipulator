An inventory destination fills up and some items stay behind.

Use case 58 · When something does not behave as expected

Help Index → When something does not behave as expected → Use case 58

In Inventory Organizer, a full destination can leave whole item stacks in their original source. Review those leftovers before applying instead of assuming every routed category was moved.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Load and confirm the intended context; back up before applying. Only one tab can hold unsynced Raw JSON at a time: leaving a tab with a red sync light asks Sync, Abandon or Cancel. Sync and compare exact values. Invalid or refused text stops the sync with a message and keeps the light red; [] is applied on Bases, Starships and Teleport Endpoints and refused on Inventory by the count rule.
  2. Inventory Raw JSON can be synced or Pretty Printed if it keeps exactly the same inventories in the same order. Organizer and Replace Items from Backup remain the simpler tools for moves and replacement.

Steps

  1. Resolve each tab’s unsynced Raw JSON before leaving it: the app asks Sync, Abandon or Cancel. Sync and verify exact values. After a parse error or refusal the text stays and the light stays red; correct it and retry. Inventory Raw JSON must keep the same inventories in the same order. (control reference)
  2. In Organizer, click Review Moves and inspect visible source/category/destination counts. Post-review rows require a positive transfer to the assigned destination: retained-only or overflow-only rows may be omitted. Do not infer that no row means no leftovers. Use a before-operation context export to inspect actual source records externally without changing the reviewed candidate. (control reference)
  3. For a destination full result, check the chosen destination and your Optional settings. With expansion off, Organizer needs a free valid cell; it does not solve crowding by merging partial stacks or discarding an item. (control reference)
  4. If acceptable, choose a different destination, enable overflow to other Container storages, or enable expansion. Overflow tries eligible unassigned containers from Container 10 backward; it is not permission to use every inventory. Expansion deliberately changes capacity. (control reference)
  5. Generate a fresh Review Moves after changing choices. Inspect the visible proposal, but remember it may omit retained-only and overflow-only rows. Apply only if wanted; afterward inspect actual sources and all destinations for leftovers. Close instead to leave inventory data unchanged and reconsider the plan. (control reference)

Expected result

  1. Organizer retains an original source occurrence unchanged when no eligible destination cell is available. Moves use whole records, changing their slot Index as needed.
  2. A review may contain useful moves and leftovers together. Closing without Apply leaves inventory data unchanged, although choices can be remembered.

What changes, and when to save

Review is private; Apply changes app memory. Only a separately confirmed File → Save writes the loaded live target. Leftovers are not a reason to overwrite the disk save prematurely.

Check the result

  1. After Apply, compare source and destination item IDs, quantities and slot locations, including duplicate stacks. Check any overflow containers and expanded capacity, not just the primary destination.

Important details and recovery

  1. Enabling expansion can expand assigned destinations even when no item moves; inspect the proposal.
