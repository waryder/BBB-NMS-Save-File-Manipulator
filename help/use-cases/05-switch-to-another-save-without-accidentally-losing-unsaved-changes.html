Use case 5 · Opening, saving, and protecting your data

Help Index → Opening, saving, and protecting your data → Use case 5

Switch saves only after deciding whether to preserve or discard the current workspace. Load Slot warns that it will replace all loaded data, including unsaved text, but it does not automatically save those edits for you.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Close No Man’s Sky. Identify both the currently loaded save and the save you want next.
  2. If current edits matter, keep a backup of the existing live files before saving the edits. A full live backup does not capture unsaved editor text.
  3. Only one tab can hold unsynced Raw JSON at a time: when you leave a tab whose sync light is red, the app asks Sync, Abandon or Cancel. Resolve that tab before structured operations, which refuse while any tab is unsynced.

Steps

  1. Keep a copy of complex edits you cannot afford to retype. Invalid or refused text is never applied: the error is shown, the text stays and the light stays red. Inventory Raw JSON must keep the same inventories in the same order.
  2. Inspect Modified Data Saved and each tab’s Raw JSON synchronization light. Red saved status means the app has recorded changes or lacks a saved live baseline. (control reference)
  3. To keep wanted edits, sync each tab and verify each intended value. Then use File > Save NMS Save File, review slot/context and require the verified result before switching. (control reference)
  4. Choose File > Open NMS Save File, confirm the destination folder and select the next Game Slot. Browsing alone does not replace the current workspace. (control reference)
  5. Click Load Slot. If you still need the current edits, choose Cancel at the replacement warning and return to them. Otherwise choose OK deliberately. (control reference)
  6. Resolve any equal-time Manual-or-Cancel decision and wait for loading to finish before inspecting the new workspace. (control reference)

Expected result

  1. A successful load replaces all four tab views and retains the newly loaded save as the future save target.
  2. Canceling replacement or the timestamp tie leaves the current loaded data and target unchanged.

What changes, and when to save

Saving current edits is a separate, confirmed live-file write. Loading the next slot changes app memory and retained target only; confirming a new folder also writes its preference. Compare the intended values before authorizing a live write.

Check the result

  1. Check the loaded-slot status and recognizable content from the new save.
  2. Confirm Live Save Loaded and Modified Data Saved are green after a successful live load. If loading fails, do not assume the target switched.

Important details and recovery

  1. A replacement warning is not a Save/Discard/Cancel dialog: OK discards the current workspace without saving it.
  2. Clipboard exports are inspection copies, not a documented full-session restoration mechanism.
