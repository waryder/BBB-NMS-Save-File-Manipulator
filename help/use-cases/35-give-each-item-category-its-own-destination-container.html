Give each item category its own destination container.

Use case 35 · Working with inventories

Help Index → Working with inventories → Use case 35

Separate the six supported item categories into six dedicated containers using explicit category destinations rather than the legacy Sorter’s target lists.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Load the intended save and confirm its active Main or Expedition context. Make a full backup before changing data.
  2. Only one tab can hold unsynced Raw JSON at a time: leaving a tab with a red sync light asks Sync, Abandon or Cancel. Sync and compare exact values. Invalid or refused text stops the sync with a message and keeps the light red; [] is applied on Bases, Starships and Teleport Endpoints and refused on Inventory by the count rule.
  3. Inventory Raw JSON can be synced or Pretty Printed if it keeps exactly the same inventories in the same order. Organizer and Replace Items from Backup remain the simpler tools for moves and replacement.

Steps

  1. Resolve each tab’s unsynced Raw JSON before leaving it: the app asks Sync, Abandon or Cancel. Sync and verify exact values. After a parse error or refusal the text stays and the light stays red; correct it and retry. Inventory Raw JSON must keep the same inventories in the same order. (control reference)
  2. If Inventory Organizer is not already open, choose Inventory Processing → Node View → Inventory Organizer before using the dialog controls below. (control reference)
  3. Click Mobile Storages to check Exosuit, Freighter, Fish Platform and available starships. Leave all stationary source boxes unchecked. (control reference)
  4. Choose Resources → Container 1, Crafted products → Container 2, Technology → Container 3, Consumables → Container 4, Trade goods → Container 5 and Special items → Container 6. (control reference)
  5. Uncheck Overflow: if destination is full, overflow to other 'Container' type storages. Uncheck Expand all Destination storages to 120 cells. Each category will use only its assigned container’s existing free cells. (control reference)
  6. Click Review Moves. Check the source/category/destination lines, then click Apply To App Data if the proposed separation is wanted. (control reference)

Expected result

  1. Each original record is classified by its saved InventoryType, not its displayed item name.
  2. Container contents already present are not automatically removed or reorganized just because that container receives a category. Full destinations can leave records in the mobile sources.

What changes, and when to save

Review Moves changes no inventory data. Apply To App Data publishes the reviewed candidate in memory, marks it modified and closes the dialog. File → Save is separate and writes the loaded save target. Organizer preferences persist even when Close cancels the proposal; neither a review nor preferences create a save backup. Before a live write, check that every intended edit is present.

Check the result

  1. Inspect all six containers after applying and inspect source inventories for retained stacks. Confirm no incorrect category destination was inherited from preferences.

Important details and recovery

  1. Use this example only when Containers 1–6 appear as available destinations; unavailable inventory records are not created.
  2. Parts counts are stack records, not the total units inside them. Assigned containers are excluded from overflow if overflow is later enabled.
