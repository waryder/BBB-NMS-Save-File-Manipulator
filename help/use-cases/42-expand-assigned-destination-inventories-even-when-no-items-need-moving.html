Expand assigned destination inventories even when no items need moving.

Use case 42 · Working with inventories

Help Index → Working with inventories → Use case 42

Expand assigned destinations without collecting any items. An empty source selection can still produce a meaningful capacity-only proposal when expansion is enabled.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Load the intended save and confirm its active Main or Expedition context. Make a full backup before changing data.
  2. Only one tab can hold unsynced Raw JSON at a time: leaving a tab with a red sync light asks Sync, Abandon or Cancel. Sync and compare exact values. Invalid or refused text stops the sync with a message and keeps the light red; [] is applied on Bases, Starships and Teleport Endpoints and refused on Inventory by the count rule.
  3. Inventory Raw JSON can be synced or Pretty Printed if it keeps exactly the same inventories in the same order. Organizer and Replace Items from Backup remain the simpler tools for moves and replacement.

Steps

  1. Resolve each tab’s unsynced Raw JSON before leaving it: the app asks Sync, Abandon or Cancel. Sync and verify exact values. After a parse error or refusal the text stays and the light stays red; correct it and retry. Inventory Raw JSON must keep the same inventories in the same order. (control reference)
  2. If Inventory Organizer is not already open, choose Inventory Processing → Node View → Inventory Organizer before using the dialog controls below. (control reference)
  3. Click Clear and leave every source inventory unchecked. Do not click a source preset afterward. (control reference)
  4. Set Resources → Container 1 and Crafted products → Container 2. Set Technology, Consumables, Trade goods and Special items to Leave where they are. (control reference)
  5. Check Expand all Destination storages to 120 cells. Uncheck Overflow: if destination is full, overflow to other 'Container' type storages. There are no source records to overflow in this setup. (control reference)
  6. Click Review Moves. Read the assigned-destination expansion notice; if a change is proposed, click Apply To App Data to publish it. (control reference)

Expected result

  1. Every assigned destination is considered for the standard 120-cell ValidSlotIndices grid, even when no items move. Unassigned inventories are not expanded by this setup.
  2. Slots and their quantities do not change. Inventory Width, Height and other metadata are not wholesale replaced. If the target lists already match, there may be no change to apply.

What changes, and when to save

Review Moves changes no inventory data. Apply To App Data publishes the reviewed candidate in memory, marks it modified and closes the dialog. File → Save is separate and writes the loaded save target. Organizer preferences persist even when Close cancels the proposal; neither a review nor preferences create a save backup. Compare every intended edit before any live write.

Check the result

  1. Inspect Container 1 and Container 2 valid-cell lists after applying, and confirm their original slot records remain intact. No transfer rows are expected with no sources.

Important details and recovery

  1. Apply can be enabled for a capacity-only candidate even when there are no item-transfer rows.
  2. The planner refuses expansion that would shrink an unusual larger grid or lose existing positions; a warning is not permission to force it.
  3. All assigned routes count, including remembered destinations for categories with no items, so reset the four unused routes explicitly.
