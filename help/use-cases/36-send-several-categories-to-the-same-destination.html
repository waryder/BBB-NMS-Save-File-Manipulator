Use case 36 · Working with inventories

Help Index → Working with inventories → Use case 36

Collect resources and crafted products into the same receiving container while retaining all other categories in their original source inventories.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Load the intended save and confirm its active Main or Expedition context. Make a full backup before changing data.
  2. Only one tab can hold unsynced Raw JSON at a time: leaving a tab with a red sync light asks Sync, Abandon or Cancel. Sync and compare exact values. Invalid or refused text stops the sync with a message and keeps the light red; [] is applied on Bases, Starships and Teleport Endpoints and refused on Inventory by the count rule.
  3. Inventory Raw JSON can be synced or Pretty Printed if it keeps exactly the same inventories in the same order. Organizer and Replace Items from Backup remain the simpler tools for moves and replacement.

Steps

  1. Resolve each tab’s unsynced Raw JSON before leaving it: the app asks Sync, Abandon or Cancel. Sync and verify exact values. After a parse error or refusal the text stays and the light stays red; correct it and retry. Inventory Raw JSON must keep the same inventories in the same order. (control reference)
  2. If Inventory Organizer is not already open, choose Inventory Processing → Node View → Inventory Organizer before using the dialog controls below. (control reference)
  3. Click Clear, then check only Exosuit and the particular available starship whose contents you want to gather. Leave Freighter, Fish Platform, all Containers, Fish Bait Box, Cooking Ingredients and other ships unchecked. (control reference)
  4. Set both Resources and Crafted products to Container 1. Set Technology, Consumables, Trade goods and Special items to Leave where they are. (control reference)
  5. Uncheck Overflow: if destination is full, overflow to other 'Container' type storages. Uncheck Expand all Destination storages to 120 cells. Both categories will share the destination’s existing free cells. (control reference)
  6. Click Review Moves and inspect both routes to Container 1. Apply To App Data only when the shared destination is intentional. (control reference)

Expected result

  1. Several categories may use one destination; the one-destination rule applies separately to each category.
  2. Whole Substance and Product records can move without merging stacks or changing amounts. Available cells are shared, so later records may remain at their sources.

What changes, and when to save

Review Moves changes no inventory data. Apply To App Data publishes the reviewed candidate in memory, marks it modified and closes the dialog. File → Save is separate and writes the loaded save target. Organizer preferences persist even when Close cancels the proposal; neither a review nor preferences create a save backup. Before a live write, check that every intended edit is present.

Check the result

  1. Inspect Container 1 for both saved category types and inspect each selected source for retained records. Confirm unrelated categories and unchecked source contents have not been gathered.

Important details and recovery

  1. The destination need not be checked as a source. Checking it adds a collection source; it does not grant receiving permission.
  2. This is not a capacity reservation for each category. Post-review rows can omit categories with no positive transfer to Container 1.
