Use case 20 · Working with bases

Help Index → Working with bases → Use case 20

Use a base’s summary label to distinguish similar names before backing it up, moving it, or deleting it. The label combines identity clues and a count of saved construction records; it is not a guarantee that the base is valid in the game.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Load the intended save and active context.
  2. If you edited Bases Raw JSON, synchronize it before relying on the Node View labels.
  3. Only one tab can hold unsynced Raw JSON at a time: when you leave a tab whose sync light is red, the app asks Sync, Abandon or Cancel. Resolve that tab before structured operations, which refuse while any tab is unsynced.

Steps

  1. Keep a copy of complex edits you cannot afford to retype. Invalid or refused text is never applied: the error is shown, the text stays and the light stays red. Inventory Raw JSON must keep the same inventories in the same order.
  2. Open Bases and expand the list root to expose the complete base records. (control reference)
  3. Read the bracketed position, Gal name, Sys, Parts and Base portions of the candidate label. Compare all of them when names repeat. (control reference)
  4. Right-click that complete record and choose Highlight In Text Box to locate its corresponding Raw JSON. (control reference)
  5. Inspect Name, GalacticAddress and Objects in the record. Return to the complete base label before choosing a base-level command. (control reference)

Expected result

  1. Gal name is derived from GalacticAddress; Sys is the system component of that address, shown in hexadecimal. Parts is the length of Objects, or zero when Objects is absent.
  2. The bracketed number is a zero-based list position and can change after sorting, insertion or deletion. The other parenthesized count describes dictionary fields, not build parts.

What changes, and when to save

Inspection and highlighting do not write a backup or save file. Any subsequent record edits remain in app memory until you explicitly save the loaded NMS context. Compare the intended values before authorizing a live write.

Check the result

  1. Check that the highlighted record has the intended name and address, especially if two bases share a name.
  2. Treat Unnamed Freighter Base as the app’s empty-name fallback, not independent proof of base type.

Important details and recovery

  1. Parts counts saved object records, not an independently measured in-game construction limit. If highlighting refuses, synchronize or rebuild the view rather than guessing a nearby JSON block.
