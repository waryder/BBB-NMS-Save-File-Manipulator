Interpret a result containing upgraded, unchanged, partially upgraded, and rejected ships.

Use case 30 · Working with starships

Help Index → Working with starships → Use case 30

Read Starship Upgrade Results as a per-slot account of the requested operation, not a single blanket success message. A mixed report can legitimately include successful upgrades, no changes, partial changes, refusals and empty slots.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Keep the report open until you have checked all selected ships and the notes below the list.
  2. Remember that these outcomes describe the loaded app data, not an automatic write to game files.

Steps

  1. Read every selected-ship row, using the slot number as well as the name when names repeat. (control reference)
  2. Treat Upgraded as an actual changed record and Already up to date as no change. A fully enabled grid can be part of an upgrade even when no extra items were needed. (control reference)
  3. For Stats/class applied; tech skipped, read Upgrade notes for the technology reason. For Rejected, read the refusal reason instead of assuming a partial upgrade occurred. (control reference)
  4. Recognize the red Slot X - (unoccupied) label as an empty-slot no-op, then close the report with OK and inspect affected records. (control reference)

Expected result

  1. Partial means approved stats/class processing applied while technology items and capacity were left as they were; the result can be partial even if those stat/class values already matched.
  2. Rejected means that ship stays unchanged, such as for an unsupported model or unusable stats/class reference. Unoccupied is separate from rejection and does not load a reference.
  3. Only actual differences cause model publication; an all-unchanged, all-rejected or empty-slot-only request adds no new edits.

What changes, and when to save

Changes stay in the loaded app data until File > Save NMS Save File writes the retained live slot and Main or Expedition context. Close No Man’s Sky and confirm that destination before saving; a green synchronization light alone does not mean the game file was saved.

Check the result

  1. Compare partial ships’ statistics/class separately from their technology layout.
  2. Confirm every selected ship is accounted for and inspect unexpected refusals before saving successful changes.

Important details and recovery

  1. Red names identify whole-ship rejections; red unoccupied labels are not rejected unnamed ships. Closing results does not undo successful or partial app-memory changes.
