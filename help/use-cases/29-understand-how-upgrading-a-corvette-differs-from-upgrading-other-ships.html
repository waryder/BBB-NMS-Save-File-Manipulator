Understand how upgrading a Corvette differs from upgrading other ships.

Use case 29 · Working with starships

Help Index → Working with starships → Use case 29

Corvette upgrades deliberately protect the existing equipment and construction instead of replacing the technology Slots array as they do for other ships. The exception is based on the saved resource scene, not the name you give the ship.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Retain a full backup and verify the active save context.
  2. Sync or abandon any unsynced Raw JSON and identify the occupied Corvette you intend to upgrade.
  3. Only one tab can hold unsynced Raw JSON at a time: when you leave a tab whose sync light is red, the app asks Sync, Abandon or Cancel. Resolve that tab before structured operations, which refuse while any tab is unsynced.
  4. Before opening Upgrade Starships, record each intended zero-based ownership index in the tree. Named picker checkboxes show no visible index: count ALL ownership-ordered rows from one, including unoccupied rows; tree index 0 is picker row 1. Cancel if you cannot identify the row confidently.

Steps

  1. Keep a copy of complex edits you cannot afford to retype. Invalid or refused text is never applied: the error is shown, the text stays and the light stays red. Inventory Raw JSON must keep the same inventories in the same order.
  2. Open Starships and inspect the target’s technology records and identity if the roster label is ambiguous. (control reference)
  3. Click Upgrade Starships and read the Corvette preservation statement alongside the non-Corvette replacement warning. (control reference)
  4. Select only the preidentified Corvette row(s) by counting every ownership-ordered row, including unoccupied rows. Named checkboxes have no visible slot index; cancel if uncertain, otherwise click OK. (control reference)
  5. Read the outcome and any Tech skipped note. Inspect the target’s retained equipment and added technology before saving. (control reference)

Expected result

  1. Existing Corvette item records, positions, module seeds and build parts are retained. Missing reference technology is counted by base technology ID, ignoring a numeric procedural seed suffix while retaining class distinctions and required duplicate counts.
  2. Only missing occurrences are added from actual matched reference records into free cells. Successful capacity processing enables sixty tech cells; it does not mean sixty installed items.
  3. Validated reference stats and S-class settings can still apply if space or layout validation skips the entire technology/capacity step. Linked construction bases and appearance are not rewritten by upgrade.

What changes, and when to save

Changes stay in the loaded app data until File > Save NMS Save File writes the retained live slot and Main or Expedition context. Close No Man’s Sky and confirm that destination before saving; a green synchronization light alone does not mean the game file was saved. Compare the intended values before authorizing a live write.

Check the result

  1. Check that retained equipment and the build are intact in app data, and inspect the actual added items.
  2. If technology was skipped, confirm the original items/layout remain and read the precise reason rather than assuming all changes were rejected.

Important details and recovery

  1. Do not expect a Corvette upgrade to replace existing module rolls or remove extra equipment. No empty-reference prerequisite applies. An unknown scene or invalid stats/class reference is rejected rather than guessed from the displayed ship name.
