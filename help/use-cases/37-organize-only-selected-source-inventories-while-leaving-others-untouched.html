Organize only selected source inventories while leaving others untouched.

Use case 37 · Working with inventories

Help Index → Working with inventories → Use case 37

Restrict gathering to two deliberately chosen sources. Keep every other inventory outside the operation except the single named receiving container.

Before you start · Steps · Expected result · Saving · Check the result · Important details

Before you start

  1. Load the intended save and confirm its active Main or Expedition context. Make a full backup before changing data.
  2. Only one tab can hold unsynced Raw JSON at a time: leaving a tab with a red sync light asks Sync, Abandon or Cancel. Sync and compare exact values. Invalid or refused text stops the sync with a message and keeps the light red; [] is applied on Bases, Starships and Teleport Endpoints and refused on Inventory by the count rule.
  3. Inventory Raw JSON can be synced or Pretty Printed if it keeps exactly the same inventories in the same order. Organizer and Replace Items from Backup remain the simpler tools for moves and replacement.

Steps

  1. Resolve each tab’s unsynced Raw JSON before leaving it: the app asks Sync, Abandon or Cancel. Sync and verify exact values. After a parse error or refusal the text stays and the light stays red; correct it and retry. Inventory Raw JSON must keep the same inventories in the same order. (control reference)
  2. If Inventory Organizer is not already open, choose Inventory Processing → Node View → Inventory Organizer before using the dialog controls below. (control reference)
  3. Click Clear, then check Exosuit and one named available starship only. Keep all other source boxes unchecked, including Container 1. (control reference)
  4. Choose Resources → Container 1. Set Crafted products, Technology, Consumables, Trade goods and Special items to Leave where they are. (control reference)
  5. Uncheck Overflow: if destination is full, overflow to other 'Container' type storages. Uncheck Expand all Destination storages to 120 cells. These settings prevent implicit spare-container writes and capacity expansion. (control reference)
  6. Click Review Moves and check that only the intended sources feed Container 1. Choose Apply To App Data only if those changes are wanted. (control reference)

Expected result

  1. Only original resource records from the checked sources are eligible to leave. Container 1 can receive without being a checked source.
  2. Unchecked inventories other than the assigned destination are not changed by this scoped setup. Records with no receiving space stay put.

What changes, and when to save

Review Moves changes no inventory data. Apply To App Data publishes the reviewed candidate in memory, marks it modified and closes the dialog. File → Save is separate and writes the loaded save target. Organizer preferences persist even when Close cancels the proposal; neither a review nor preferences create a save backup. Before a live write, check that every intended edit is present.

Check the result

  1. Inspect the two sources and Container 1 after applying. Compare any inventory that you intended to protect with its pre-operation state before File → Save.

Important details and recovery

  1. Unchecked means not a gathering source, not universally protected from writes: assigned destinations and enabled overflow can still receive.
  2. Selecting a source equal to its category destination keeps that category there and does not send it to overflow.
  3. Avoid Select all, Mobile Storages or Stationary Storages after manual selection unless you intend to replace that selection.
