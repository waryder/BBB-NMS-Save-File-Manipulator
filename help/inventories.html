Inventory Processing

Important limitations before using these controls

  1. Only one tab can hold unsynced Raw JSON at a time: leaving a tab whose sync light is red (by mouse or keyboard) opens Unsynced Raw JSON with Sync, Abandon and Cancel. Sync applies the text and switches only if it succeeds; Abandon reloads that tab’s Raw JSON from the app data; Cancel stays on the tab. Structured operations still refuse while any tab is unsynced. Inventory Raw JSON can be synchronized and Pretty Printed like the other tabs, provided it keeps exactly the same inventories in the same order.
  2. An import error does not guarantee an unchanged destination. The helper can expand ValidSlotIndices before it reads the backup’s Slots, so a backup missing Slots can fail after capacity already changed; there is no rollback around this helper. Do not retry or save blindly. Inspect target capacity and items, preserve needed work, and deliberately reload from the saved baseline if abandoning the failed replacement. A filename extension does not validate structure; use a known complete inventory export.
  3. Inventory Processing Raw JSON lists every non-empty inventory in a fixed order. Sync to Node View and Pretty Print replace each inventory’s contents in place. The edited text must keep exactly the same number of inventories, in the same order, and each entry must be a non-empty JSON object; otherwise the sync is refused with Raw JSON Not Applied and nothing changes. An empty array ([]) is refused. Inspect actual fields before saving.

Gather from these sources

Choose inventories whose whole saved slot/stack records may be gathered. Parts means records, not individual quantity units: the organizer does not split/merge stacks or change amounts. Optional

Inventory Processing → Node View → Inventory Organizer → Optional → Expand all Destination storages to 120 cells.

Expand all Destination storages to 120 cells.

Expands every assigned destination, even if no record moves to it. With expansion enabled, an overflow container also expands when it receives records. With expansion off, existing unoccupied valid cells determine capacity and no destination is automatically expanded. Checked by default unless saved preferences say otherwise.

Review Summary

Read-only proposal display. Before review it shows current source/category routes without move counts. After review it summarizes the proposal; the current renderer may omit overflow-only or retained-only rows, so absence of a row is not a complete inventory audit.

Inventory Processing → Node View → Inventory Organizer → Review Moves

Review Moves

Creates a private proposal without publishing inventory changes. Disabled when no sources are selected and expansion is off. Requires synchronized Raw JSON in every tab and valid loaded context. Any source, route or option change invalidates this review.

Before using Review Moves, read the shared safety limitations for this page.

Inventory Processing → Node View → Inventory Organizer → Review Moves → Reviewing inventory moves, please wait…

Reviewing inventory moves, please wait…

The text-only notice reads exactly: Reviewing inventory moves, please wait…

Review Moves owns this non-cancellable modal while constructing the private proposal. It dismisses progress in cleanup after planning returns or fails, restores interaction, then renders the review or reports an error. No inventory change is published by Review.

There are no Cancel or Close buttons in this notice. Wait for the owning operation to finish; no separate user-dismissal or cancellation control is provided here.

Inventory Processing → Node View → Inventory tree

Inventory tree

Expand an inventory to inspect its fields and stored slot records. Inventory drag/drop is not enabled by the initial tree configuration.

Inventory Processing → Node View → Inventory tree → Right-button drag selection → Delete N Nodes

Right-button drag selection → Delete N Nodes

The shared right-button range-selection handler can expose Delete N Nodes even on this tab, although its ordinary right-click menu has no Delete Node item. Confirmation removes the selected structure through the generic handler; removing a whole inventory record is refused, because Inventory Processing must keep its count and order. This is structural deletion, not the category-based Organizer; do not use it casually on inventory fields.

Before using Right-button drag selection → Delete N Nodes, read the shared safety limitations for this page.

This tree-to-model path uses the same in-place inventory replacement and the same count, order and object checks as Raw JSON sync; a mismatch is refused without changing data. Inspect actual model data before saving.

Inventory Processing → Node View → Right-button drag selection → Delete N Nodes → Delete Nodes — confirmation

Delete Nodes — confirmation

Review Delete (N) nodes from the Tree? before acting. For a base or generic tree deletion the selected visible-node count can include expanded child fields. The starship-specific controller instead deduplicates complete occupied ship slots and validates the complete request.

Before using Delete Nodes — confirmation, read the shared safety limitations for this page.

Inventory Processing → Raw JSON

Raw JSON

Contains the inventory data exposed by this tab.

Inventory Processing → Raw JSON → Synched to Node View — status indicator

Synched to Node View — status indicator

Red means this tab’s Raw JSON has edits that have not been applied to the app data, including text that failed to parse or was refused. Green means the text and Node View match the app data. Neither color means a live save was written.

If the Raw JSON is not valid JSON, Sync to Node View and Pretty Print show the error and stop: your text stays in the editor, the sync light stays red and Node View keeps showing the app data. Valid JSON that is not an array is refused with Raw JSON Not Applied. Valid JSON is also refused, with the reason and the entry number, when this app could not process it: every entry must be a JSON object with the fields the app reads (Name on every tab; GalacticAddress on Bases; UniverseAddress with RealityIndex and GalacticAddress numbers on Teleport Endpoints), Starships may hold at most 12 entries, and Inventory must keep its count and order. An empty array ([]) is applied like any other array on Bases, Starships and Teleport Endpoints; on Inventory it is refused by the count rule. Correct the text and retry, or leave the tab and choose Abandon to reload the app data.

For Synched to Node View — status indicator: Inventory Raw JSON must keep exactly the same inventories in the same order; see the inventory rule above.

Inventory Processing → Raw JSON → Pretty Print

Pretty Print

For Pretty Print: Inventory Raw JSON must keep exactly the same inventories in the same order; see the inventory rule above.

Pretty Print is not display-only: it attempts a model update from the editor, reloads indented text from the model and rebuilds Node View.

Before using Pretty Print, read the shared safety limitations for this page.

If the text is invalid or refused (for example a changed Inventory count or a missing required field), Pretty Print shows the reason and stops without changing your text; the sync light stays red. Formatting does not write a game file; compare actual values before saving.

Inventory Processing → Raw JSON → JSON text editor

JSON text editor

Displays this tab’s inventory-view data. You can edit the JSON directly. Line numbers identify text lines; the current line is highlighted. Text is not line-wrapped, so long lines scroll horizontally.

Text editing is not an automatic model update or disk write. Pending text stays on its tab: you cannot switch tabs without choosing Sync, Abandon or Cancel, so a sync on another tab cannot overwrite it.

For JSON text editor: Inventory Raw JSON must keep exactly the same inventories in the same order; see the inventory rule above.

The editor displays line numbers and does not wrap long JSON lines. Use the editor’s own horizontal scrollbar to inspect a long value. Selecting or copying text does not edit the save; typing, cutting, deleting or pasting does. A text edit is not automatically a successful synchronization or a disk save.
